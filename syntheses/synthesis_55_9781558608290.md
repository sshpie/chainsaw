# 55. Bioinformatics: Managing Scientific Data

Book 55 is our data-management substrate for the whole bio-compute lobe. Where books 56-65 run algorithms on biological data, this 2003 Lacroix-and-Critchlow volume asks the prior question: how do we get consistent, queryable access to that data when it lives in hundreds of autonomous, heterogeneous, format-drifting sources. The answer it surveys is not one system but eight, each a different point in a shared design space, and the lasting value is the map of that space.

The core thesis is that syntax is easy and semantics is hard. Connecting N sources point to point costs N(N-1)/2 programs; a mediator with a shared model and one wrapper per source collapses that to N. But wrappers only solve format. The real cost sits in semantic heterogeneity: concept identification (do two records name the same gene), concept overloading (both sources say 'gene' but one means postulated and one means known-coding), and reconciliation where there may be no right answer because two sources legitimately disagree on the same sequence. We carry this straight into recon: correlating a host across Shodan, Censys, and CT logs is the same entity-resolution problem, and 'which record is authoritative' is our verification stage, not a footnote.

The design axis runs warehouse to federation to mediator. A warehouse (GeneExpress GXDW, 5GB of gene annotations, refreshed quarterly) materializes everything: faster, secure behind a firewall, but stale and costly to maintain. A federation or mediator leaves data at the source, always current, cheaper on disk, but pays translation and network cost at query time. The honest verdict, restated in the concluding remarks, is that scalability and semantic consistency are mutually exclusive goals; a system excels at one and settles for the other. That tradeoff discipline is the transferable lesson.

The systems are worth knowing by name. SRS indexes flat files with the Icarus meta-language and bi-directional indexed links. Kleisli exposes a complex-object model (sets, bags, lists, records, variants) through CPL and sSQL, grounded in nested relational calculus and monads, and optimizes by pushing projections, selections, and joins down into the RDBMS. TAMBIS drives queries from an ontology (the TaO, ~1800 concepts in GRAIL description logic) that sanctions only meaningful concept combinations. DiscoveryLink, the IBM Garlic descendant, is the strongest engineering: SQL over wrappers, a five-step registration (CREATE WRAPPER, SERVER, NICKNAME, FUNCTION MAPPING, user mapping), and a cost-based optimizer that takes query-specific plans and cost estimates back from each wrapper, the only surveyed system that does so. K2 uses ODMG and K2MDL; P/FDM uses the functional data model, Daplex, and a Prolog query splitter; KIND lifts sources to conceptual models plus domain and process maps compiled to F-logic.

Two operational truths recur. First, sources change their formats and interfaces roughly every six months, so any integration must tolerate schema drift or it silently breaks. Second, query optimization is not theater: the same BLAST call can take seconds or hours depending on inputs, so a cost model that consults the source beats any fixed heuristic. Chapter 13 gives us the evaluation rubric we reuse for any data system: six metrics (efficiency, extensibility, functionality, scalability, understandability, usability) across implementation and user perspectives, with precision and recall for the text-retrieval parts.

We reach for this book when the task is fusing many messy sources under one queryable view, when we need the warehouse-versus-federation call, or when provenance, data quality, and HIPAA exposure ride along with the integration. The vocabulary is twenty years old, but the problem shape is exactly today's RAG-and-pipeline problem.
