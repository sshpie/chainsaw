## One-liner

A pattern-catalog playbook by Arsanjani and Bustos that treats agentic AI as a software-engineering discipline: 40-plus named design patterns, three interlocking maturity models, and a worked loan-processing system built in Google ADK, CrewAI, and LangGraph.

## Thesis

An agent is not a prompt; it is an engineered system with an anatomy (reasoning engine plus tools, memory, planning) that must be built from reusable, named architectural patterns rather than from one long fragile system prompt. The book argues that the difference between a failed "science project" and a transformative product is adopting a "pattern-first" architecture: select patterns to balance the opposing forces of a problem before writing code, anchor progress to three aligned maturity models (organizational GenAI, agentic-reasoning spectrum, engineering implementation), and treat governance, observability, and AgentOps as day-one requirements rather than afterthoughts. The goal is never to "build an agent" but to solve a specific business problem with one.

## Structure

- Part 1 (Foundations, Ch1-4): GenAI in the enterprise, AgentOps, the distinction between an LLM call / a workflow / a true agent, three maturity lenses, agent anatomy (Sense-Reason-Plan-Act-Memory), and the agentic stack (Function Calling, Anthropic's MCP for agent-to-tools, Google's A2A for agent-to-agent, described as 'SMTP for AI agents').
- Part 2 (the pattern catalog, Ch5-11): each pattern documented with a fixed template of Context / Problem (with Forces) / Solution / Example / Python implementation / Consequences (pros and cons) / Implementation guidance.
- Ch5 Coordination patterns (Supervisor/Task Delegation, Multi-Agent Planning, Agent Router/Tool Routing, Consensus, Agent Negotiation, Resource Allocation, Conflict Resolution) and Ch6 Explainability & Compliance (Instruction Fidelity Auditing, FCoT Embedding, Persistent Instruction Anchoring, Shared Epistemic Memory).
- Ch7 Robustness & Fault Tolerance (16 patterns over a 5-level maturity ladder: Adaptive Retry with Prompt Mutation, Watchdog Timeout Supervisor, Auto-Healing Resuscitation, Incremental Checkpointing, Majority Voting, Agent Self-Defense, Agent Mesh Defense, Execution Envelope Sandboxing, Fallback Model Invocation, Trust Decay and Scoring, Canary Agent Testing) and Ch8 Human-Agent Interaction (Agent Calls Human, Human Delegates to Agent, Human Calls Agent, Agent Delegates to Agent, Agent Calls Proxy Agent).
- Ch9 Agent-level patterns (Single-Agent Baseline, Agent-Specific Context and Memory, RAG, Structured Reasoning and Self-Correction, Multimodal Sensory Input), Ch10 System-level for production (Tool and Agent Registry, Real-Time Compliance Monitoring, Agent Authentication and Authorization, Event-Driven Reactivity), Ch11 Advanced Adaptation (Self-Improvement Flywheel, R5 model, Custom Evaluation Metrics, Synthetic Data Generation, Model Tuning, Adversarial Red Teaming, Tokenomics/ROI).
- Part 3 (Execution, Ch12-16): a 3-level practical implementation roadmap, a single-agent loan processor built in Google ADK with FCoT (Ch13), its re-architecture into a multi-agent supervisor system (Ch14), the same use case reimplemented in CrewAI and LangGraph with a head-to-head comparison (Ch15), and a closing action plan with two mini case studies (Ch16).

## Core ideas

1. Three interlocking maturity models, aligned in a master table (Table 16.1) into phases Foundational/Augmented/Production/Autonomous/Orchestrated/Self-learning: the GenAI Maturity Model (Ch1, L0 data foundation to L6 multi-agent) is the strategic roadmap; the Agentic AI Maturity Spectrum (Ch3, L1 basic agentic to L6 self-correcting, passing through ReAct/Reflexion introspection at L3) is the architectural blueprint; and the Implementation Maturity Levels (Ch12, L1 monolithic POC to L3 self-improving MLOps ecosystem) is the engineering discipline. The warning is to avoid 'architectural overreach' by keeping all three aligned.
2. An agent has an anatomy that separates it from a stateless LLM call: a reasoning engine (the LLM) given a 'body' of tools (APIs/functions to perceive and act), memory (short-term scratchpad plus long-term vector store or managed memory bank), and a capacity for planning and execution. 'Context is king.'
3. The agentic stack rests on three communication layers: Function Calling / Tool Use as the base, the Model Context Protocol (MCP, Anthropic, vertical, agent-to-tools), and the Agent2Agent protocol (A2A, Google, horizontal, agent-to-agent, now a Linux Foundation project), discovered via an Agent server and Agent card.
4. Pattern-first architecture is the central conceptual shift: stop thinking like a 'prompt engineer' and start thinking like a 'system architect.' Patterns are reusable, proven blueprints that resolve the opposing 'forces' in a problem space; 'patterns generate architectures.' A 30-minute whiteboard sketch of tools, memory, and pattern arrows should precede any code.
5. FCoT (Fractal Chain-of-Thought) is the book's signature reasoning pattern: a recursive, self-correcting RECAP -> REASON -> VERIFY loop governed by an Instruction Contract (with an IC-Fingerprint) and a dynamically closing 'context aperture,' designed to prevent goal drift and instruction drift in multi-step tasks.
6. Robustness is treated as its own discipline with a 16-pattern maturity ladder, distinguishing transient failures (handled by Adaptive Retry with exponential backoff) from persistent ones (Circuit Breaker, Fallback Model), and adding adversarial defenses (Agent Self-Defense, Agent Mesh Defense) and sandboxing (Execution Envelope Isolation).
7. Human-Agent Interaction is framed as five directional patterns (who calls whom), with Human-in-the-Loop positioned as the non-negotiable guardrail for irreversible high-stakes actions: the recurring design move is to give an agent a draft_report tool but withhold the submit_report tool until a human approves.
8. The continuous-improvement engine is the Self-Improvement Flywheel (Generate -> Evaluate -> Learn -> Deploy) plus the R5 operational model (Relax, Reflect, Reference, Retry, Report) and advanced tuning options (SFT, PEFT via LoRA/adapters/prefix/prompt-tuning, DPO) over full reinforcement learning.
9. Evaluation must be 'logic-aware,' not just surface overlap: the book criticizes BLEU/ROUGE/BERTScore/BLEURT as 'logic-blind' and introduces custom metrics like STEPScore (step-coverage F1 minus an ordering penalty) alongside SelfCheckGPT-style stochastic-consistency checks and Reflexion-style verbal self-feedback.
10. Governance, observability, and AgentOps are day-one requirements, not afterthoughts: an agent's larger 'blast radius' versus a RAG system demands audit trails, bias/fairness testing on a 'golden dataset' for demographic parity, PII redaction, and traceability via LangSmith or OpenTelemetry/Cloud Trace so an auditor can later see exactly why a decision was made.
11. Frameworks accelerate but do not replace design: choose the framework to fit the patterns, not the reverse, and design around stable interfaces (tool contracts, explicit state schemas, pattern-based orchestration) to avoid framework lock-in in a volatile landscape.
12. The architectural progression from a Level 3 monolithic single agent to a Level 4 multi-agent team is driven by separation of concerns, fault isolation, and division of cognitive labor, which solves the 'lost in the middle' problem of an over-long single prompt by giving each specialist a short, focused instruction set.

## Techniques and methods

- The pattern documentation template applied uniformly: Context, Problem (with explicit Forces), Solution, Example, Python implementation example, Consequences (pros and cons), and Implementation guidance, so each of the 40-plus patterns is decision-ready.
- Building a single-agent loan processor in Google ADK: define Python tool functions (validate_document, run_credit_check, assess_risk, check_compliance), wrap them in FunctionTool, attach a BuiltInPlanner with ThinkingConfig(include_thoughts=True, thinking_budget=1024), and drive an LlmAgent on gemini-3-flash via a Runner and InMemorySessionService.
- Encoding FCoT directly into the agent_instructions as an INSTRUCTION CONTRACT carrying an IC-Fingerprint (e.g. 'LOAN-FCoT-v3-Delta0710') plus an N=3 recursive RECAP/REASON/VERIFY loop, then exposing the agent's internal monologue through ADK's ThinkingConfig for observability and debugging.
- Re-architecting into a Supervisor/Orchestrator multi-agent system: promote each tool into its own LlmAgent specialist, wrap each in ADK's AgentTool to implement Agent-Delegates-to-Agent, and have the orchestrator act as a semantic data mapper that extracts fields from one agent's JSON output (e.g. customer_id) and forwards them as the next agent's input via contextual state rather than a Python dict.
- Production-hardening the runner with stacked decorators: @sleep_and_retry and @limits(calls=15, period=60) for rate limiting, and tenacity's @retry with stop_after_attempt(5) and wait_exponential(multiplier=2, min=4, max=30) gated on a RESOURCE_EXHAUSTED/429 detector, plus professional error handling that diagnoses free-tier quota caps.
- Implementing the same workflow in CrewAI: define Agents by role/goal/backstory, define chained Tasks with a context parameter for implicit state passing, assemble a Crew with Process.hierarchical and a manager_agent, set temperature=0.0 for deterministic tool use, and call kickoff(inputs=...).
- Implementing the same workflow in LangGraph: define a TypedDict LoanGraphState, write each step as a node function that returns state updates, wire conditional edges (decide_after_fetch, decide_after_validation, etc.) that route to a compile_rejection terminal node on an 'error' key for fail-fast control flow, then compile and run via stream()/invoke().
- Enforcing data contracts between agents by returning JSON-encoded strings ({"status":"validated",...} on success or {"error":...} on failure) with strict Pydantic schemas recommended, and using structured-output forcing instead of fragile string matching to parse LLM risk verdicts.
- Heterogeneous model selection across a team: assign a lightweight low-latency model (Gemini Flash) to a document validator and a stronger reasoning model (Gemini Pro) to a compliance checker, keeping behavior consistent via strict FunctionTool definitions.
- The proxy-tool technique (Agent Calls Proxy Agent): wrap a tool's _run method so it forwards to an external ML risk-decision engine or API, keeping critical business logic centralized and governable rather than embedded in the agent.
- The pattern-first design exercise: draw the reasoning box, add tool and memory boxes, then connect them with arrows that each name a pattern (ReAct loop, Adaptive Retry on a failing tool, an arrow to a Human box for Human-in-the-Loop, an arrow to a Logs DB for Instruction Fidelity Auditing) before writing any code.
- AgentOps starter loop for practitioners: containerize the agent with a Dockerfile, serve it as a FastAPI/Flask endpoint, log structured thoughts/tool-calls (not just final answers) via Instruction Fidelity Auditing, and deploy to Cloud Run or Lambda to watch request count, error rate, and latency.

## Memorable

- The recurring loan-origination domain runs as a 5-stage pipeline: document intake, credit check, risk assessment, compliance review, final decision. Borrower-789 ($250,000) is the 'happy path' approval; Borrower-400 ($350,000) returns credit score 450 with a 'compromised credit history' and is denied at high risk, while the compliance check still runs to satisfy Fair Lending / ECOA.
- The denied-path trace shows the agent weighing contradictory evidence: documents pass, credit score 680, but a risk score of 8 trips the compliance tool ('Policy violation: Risk score of 8 is too high for approval'), and the orchestrator correctly prioritizes the hard failure over the earlier successes.
- Concrete tool thresholds in the multi-agent version: a credit score below 600 is an immediate high-risk failure; the risk formula adds +4 below 650, +2 below 720, and +5 when loan-to-income exceeds 0.8; a risk score of 8 or higher is non-compliant; 'No History' is an automatic denial. Mock scores: CUST-12345 = 810 (approve), CUST-55555 = 620 (high-risk).
- FCoT is fingerprinted with an Instruction Contract tag 'LOAN-FCoT-v3-Delta0710' and runs an N=3 recursive loop; the agent on gemini-3-flash uses thinking_budget=1024 and include_thoughts=True so its reasoning is observable.
- Free-tier reality check baked into the error handler: roughly 20 requests/day hard cap, and the diagnostic literally tells the operator '[1] Wait 24 Hours' or '[2] Enable Billing (Pay-As-You-Go)' instead of dumping a Python traceback.
- The ROI argument: an agent resolving a request for about $0.50 versus roughly $12.00 for a human, with a worked example saving on the order of $45,000 in a single month; learning loops carry a training-token multiplier of roughly 10x to 100x.
- STEPScore is defined as step-coverage F1 minus an order penalty, introduced because classic metrics (BLEU, ROUGE, BERTScore, BLEURT) are dismissed as 'logic-blind' for reasoning evaluation.
- The A2A protocol is pitched as 'SMTP for AI agents' and is now an official Linux Foundation project governed by a cross-industry steering committee, enabling a future 'economy of agents' that discover, negotiate, and recruit each other.
- The CrewAI-versus-LangGraph contrast is made tangible: in the invalid-input case CrewAI's intermediate agents keep running unnecessary credit and risk steps after validation already failed, whereas LangGraph's conditional edges fail-fast straight to the rejection node, saving API cost and latency.
- Two closing mini case studies: a regional bank's Suspicious Activity Report (SAR) drafting agent that uses Instruction Fidelity Auditing plus a draft_report-only tool to cut drafting time 80% with 100% human oversight; and an IT remediation agent that, without patterns, hallucinated a deleted server during a network blip and tried to provision an expensive new cluster, fixed via Adaptive Retry and Self-Correction.
- The 'first real project' prescription for practitioners: a GitHub-monitoring agent with get_latest_issues and send_email tools, an Adaptive Retry wrapper on the flaky API, and a Human-in-the-Loop gate that prints its email plan and waits for the operator to type 'yes' before sending.
- Authors Dr. Ali Arsanjani and Juan Pablo Bustos close with 'maturity is not an accidental outcome, it is the calculated result of intentional, pattern-driven investment' and the final line 'Go build the future.'

## Curriculum fit

Fits as a capstone / advanced module in an applied AI-engineering or LLM-systems curriculum, sitting after students already understand LLM basics, prompting, and RAG. Strongest use is the bridge from 'I can call an LLM' to 'I can architect a production agentic system': the three maturity models give a grading rubric for project ambition, Part 2's pattern catalog is a ready-made reference for design reviews, and Part 3's loan-processing build (ADK -> multi-agent -> CrewAI/LangGraph) is a turnkey hands-on lab with a public GitHub repo. Pair the pattern-first design exercise and the practitioner action plan (master one framework, think in patterns, build AgentOps muscle, champion responsible AI) as recurring assignment scaffolds. It complements rather than replaces a hands-on framework cookbook; it is heavier on architecture, governance, and decision-making than on exhaustive code, and its specific model/version references (gemini-3-flash, framework APIs) will date faster than its durable pattern and maturity content. Best for senior undergraduates, graduate students, or practicing engineers and solution architects in regulated-industry contexts (finance, compliance, enterprise IT).
