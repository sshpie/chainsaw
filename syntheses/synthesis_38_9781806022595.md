## One-liner

A hands-on, opinionated field guide to Claude Code built around one organizing thesis: context engineering (writing, selecting, compressing, isolating context) is the real skill behind effective agentic coding, taught by building a single project (HookHub) across every feature from CLAUDE.md to deep agents.

## Thesis

The author (Eden Marco, a Google Cloud LLM specialist and LangChain Ambassador) argues that modern coding agents are "wrappers around LLMs," but that the wrapper, the agent harness, is where all the real engineering lives, and that the load-bearing discipline of that harness is context engineering. Because context is dynamic (not static like a prompt) and grows with every tool call until it "rots," the central job of both the tool builder and the everyday developer is to manage what enters the finite context window. The book operationalizes this through LangChain's four-strategy framework (Write, Select, Compress, Isolate context) and shows that every Claude Code primitive, CLAUDE.md memory, /clear and /compact, subagents, skills, output styles, scoped MCP, Git worktrees, is best understood as a concrete instance of one of those four strategies. The deeper payoff is a definition of "deep agents" (planning tool + subagents + filesystem + large system prompt) that explains why Claude Code can sustain long-horizon tasks where shallow ReAct agents collapse under context bloat.

## Core ideas

1. The agent harness, not the LLM call, is where engineering happens. The model invocation is 'often straightforward'; reliability comes from how the surrounding system manages state, tools, memory, and most importantly which context is sent at each step.
2. Context engineering is the evolution of prompt engineering because 'prompts are static, while context is extremely dynamic.' Garbage in, garbage out. The four strategies are Write (persistent memory), Select (intelligent retrieval), Compress (/clear, /compact), Isolate (subagents).
3. Three named context failure modes recur throughout the book: context poisoning (a hallucination enters context and corrupts future output), context confusion (irrelevant context influences the response), and context clash (contradictory context). Together these are later called 'context rot.'
4. Claude Code memory is a layered hierarchy with strict precedence: Level 1 Managed Policy (org, cannot be overridden), Level 2 User (~/.claude/CLAUDE.md), Level 3 Project (./CLAUDE.md), Level 4 Project Rules (.claude/rules/*.md), Level 5 Project Local (CLAUDE.local.md, git-ignored). Upward discovery loads parent dirs; nested memory is lazy-loaded only when those subdirs are touched.
5. Subagents are the isolation primitive: each runs in its own context window, receives only the single prompt the main agent constructs, and returns one condensed response, so heavy work never bloats the main thread. The description field controls both WHEN a subagent is invoked and HOW the main agent prompts it.
6. Skills use 'progressive disclosure': only the YAML front matter (name + description, ~100-200 tokens per skill) is loaded at startup; the SKILL.md body and any auxiliary scripts load only when the skill is actually selected. A skill is just a packaging mechanism, it can wrap deterministic scripts, AI calls, or both, and the agent falls back to its own reasoning if a script fails.
7. MCP's biggest weakness is context pollution: all tool definitions must be preloaded into the system prompt. The book's concrete number is that 58 tools across GitHub/Slack/Central MCP can consume 55,000 tokens before the conversation begins; the fix is scoped config (.mcp.json.tavily) plus --strict-mcp-config, which dropped MCP context from ~20% to ~2.4% in the worked example.
8. A deep agent is defined by four implemented capabilities (per LangChain): an explicit planning tool (a Markdown to-do list, surfaced in Claude Code as TodoWrite/TodoRead), subagents for hierarchical delegation, filesystem access for offloading intermediate state, and a large system prompt. Shallow ReAct agents lack these and degrade as iterative tool-calling accumulates context.
9. The system prompt should hit the 'Goldilocks zone': overly specific prompts treat the LLM as a deterministic state machine (hardcoded 'ask exactly three follow-up questions'), overly vague prompts give insufficient signal ('act consistent with the brand'). The right prompt gives a reasoning framework, not a flowchart, and uses heuristics like 'choose the simplest solution' (described as a greedy-algorithm heuristic).
10. The filesystem is a 'context engine.' Using the available-context / selected-context / required-information (blue/red/green) model, the goal of context engineering is to make the selected set as small as possible while still fully covering what the task requires, avoiding under-retrieval, over-retrieval, misaligned retrieval, and context-window overflow.
11. Parallel agents are powerful but conditionally counterproductive: tightly coupled features, shared-state/ordering constraints (config files, migrations, shared types), small tasks (session overhead exceeds savings), high coordination cost, and exploratory work all argue for sequential execution. Rule of thumb: start sequential, parallelize only after confirming tasks don't interact.
12. Skills must follow the principle of least privilege, and so must subagents (and scoped slash-command allowed-tools). Over-provisioning tools is 'tool pollution' that adds tokens and widens the security surface; a malicious subagent description or untrusted skill is a real threat because the description is appended to the main agent's system prompt.

## Techniques and methods

- Spec-driven design over vibe coding: use plan mode (Shift+Tab / /plan, read-only) with a heavier model (Opus) to generate and iteratively refine a SPEC/CLAUDE.md, then implement against it with Sonnet, tagging the spec with @.
- The five-level memory hierarchy plus the # hashtag quick-add and /memory editor; demonstrated with the pizza (project memory) vs hamburger (user memory) recall test.
- Context-switching hook: a context-switcher.sh wired to the UserPromptSubmit hook that idempotently appends @-imports to CLAUDE.md based on git branch or query keywords, using grep -qxF to stay safe against duplicate imports.
- Scoped MCP context engineering: project (.mcp.json) vs user vs session scope, the claude --mcp-config <file> flag, and --strict-mcp-config to ignore the default hierarchy entirely; verified with /context.
- Subagent shaping: editing the description to control invocation AND the prompt the main agent constructs ('simplify to the GIST'), plus editing the SKILL/agent body to control output formatting, demonstrated end to end on the Mermaid diagram subagent.
- The Infinite Agentic Loop / /infinite slash command (from IndieDevDan): a high-order 'meta-prompt' that takes spec_file, output_dir, count as $ARGUMENTS and spawns N subagents in waves (1-5 all at once, 6-20 in batches of 5) to generate competing implementations (six Hero variants) you then pick from.
- Hardened commit-message skill using allowed-tools front matter (Bash(git add:*), git status, git commit) plus shell-injected context (!`git status`, !`git diff HEAD`), framed explicitly as retrieval-augmented generation and least privilege.
- Custom output styles as system-prompt replacement: minimal-bullets, yaml-concise (format-as-meaning), and a retro-ASCII HTML blog style that embeds workflow rules to auto-write and open generated .html files.
- Custom status line in Python run via uv, reading Claude Code's JSON from stdin to display the active output_style, with ANSI color, and an advanced version that parses the session JSONL at transcript_path to surface the last user prompt.
- GitHub automation: gh CLI auth + Claude GitHub App + the claude.yaml / claude-code-review.yaml Actions workflows (token stored as the CLAUDE_CODE_OAUTH_TOKEN secret), tagging @claude on issues, and adding CLAUDE.md to fix the broken-rename failure.
- Parallel local+cloud orchestration via Git worktrees in Claude Desktop: Local-worktree vs cloud mode, auto-named worktrees (vigilant-fiestel, zealous-jemison, suspicious-bassi), a temporary project/hookhub-merge integration branch, test-before-push, and mobile/cloud execution.
- Running a skill in isolation with context: fork + agent: Explore front matter, and disable-model-invocation: true to force slash-only invocation.

## Memorable

- The recurring HookHub project: a Next.js marketplace that displays open-source Claude Code hooks as cards linking to GitHub repos, built incrementally as the book's single running example.
- Concrete token-cost numbers: 58 tools across GitHub/Slack/Central MCP = ~55,000 tokens before any conversation; in the worked example MCP context dropped from ~20% to ~2.4% with --strict-mcp-config; a skill costs only ~100-200 tokens per skill at startup; five MCP servers can cost 50,000 tokens.
- The Shakespeare/Mandarin analogy (from Cloudflare's CodeMode): forcing an LLM to use JSON tool-calls is like 'putting Shakespeare through a short Mandarin course and asking him to write a play in Mandarin', because models saw lots of real-world code but very few real tool-call examples.
- The deliberately-broken IceBreaker demo: Claude renames linkedin_username to linkedin_url without a CLAUDE.md, silently breaking a third-party API contract, then gets it right once repository context is supplied. The book leans into this failure as a teaching moment ('Spoiler ahead!').
- Claude's status while analyzing the repo is shown literally as 'Booping', and the Anthropic 'Goldilocks zone' for prompts (not too vague, not too detailed) is cited from Anthropic's 'Effective Context Engineering for AI Agents.'
- The pirate commit message: smart_commit.sh is edited to call claude -p so the deterministic script invokes the Claude CLI to write a commit message 'like a pirate', creating a layered AI-inside-script-inside-skill composition.
- The disclaimer's notable framing: the author is a Google LLC employee writing a personal book about Anthropic's Claude Code, with explicit trademark and non-affiliation notices for both companies.
- Datable specificity: Claude Code plugins published Oct 9, 2025, exactly one day after Google's Gemini Extensions (Oct 8, 2025); agent skills introduced Oct 2025; the book runs Claude Code v2.1/2.2 with Sonnet 4.5; first published March 2026.
- Heroes named like a startup team (Vinay frontend, Rajesh backend, Alex DevOps) to illustrate role-based parallel Claude instances; auto-generated worktree names vigilant-fiestel and zealous-jemison become running characters in the Desktop chapter.
- The CAIR metric (Cost of AI Recovery, from a LangChain blog) is invoked to justify why the rewind/checkpoint feature, which retains checkpoints for up to 30 days but does NOT track Bash commands or manual edits, matters for adoption.

## Curriculum fit

Strong fit as the practitioner-facing, single-tool deep dive in an agentic-engineering curriculum, positioned AFTER foundational LLM/RAG/ReAct material (the book explicitly assumes Python/TypeScript, Git, and prior agent-building experience; it is 'not a beginner-level book'). It pairs naturally with a vendor-neutral MCP course (the author cross-sells his own; Packt's companion MCP-with-Python/TypeScript titles are the obvious sequels) and with a LangChain/deep-agents track, since Chapters 9-11 explicitly bridge Claude Code primitives to LangChain DeepAgents and the ReAct paper. Best used as a hands-on lab module: every concept maps to a reproducible exercise on the HookHub repo. Caveats for course design: the content is highly version-sensitive (Claude Code v2.1, Sonnet 4.5, Oct-2025 feature dates) and will date quickly, several screenshots/UI flows are not reproducible step-by-step (the author says so for the Desktop chapter), and the text shows light editing slips (a duplicated chapter title, OCR-style typos like 'pec-driven' and 'feistel/fiestal'). Its durable, exam-worthy core is conceptual: the four context-engineering strategies, the deep-agent definition (planning + subagents + filesystem + system prompt), least-privilege tool scoping, and progressive disclosure, which transfer to any agent harness, not just Claude Code.
