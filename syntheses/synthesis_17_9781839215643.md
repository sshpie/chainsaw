# SQL Injection Strategies: Practical techniques to secure old vulnerabilities against modern attacks

ISBN: 9781839215643  |  Book #17

## One-liner
A short, hands-on Packt primer (three EY/Italian security-consultant authors) that walks a beginner from SQL fundamentals through manual and automated SQL injection against a deliberately vulnerable OWASP lab, then through layered code- and platform-level defenses, ending with a perspective chapter on the vulnerability lifecycle.

## Thesis
SQL injection persists 20-plus years after discovery because it is an application-level coding error, not a database flaw: applications build queries by concatenating untrusted user input into SQL strings, and the database faithfully executes whatever syntactically valid statement reaches it. The cure is not one control but defense-in-depth applied simultaneously across input validation, parameterized queries, character escaping, secure coding, and platform protections (WAFs, database firewalls, encryption, least privilege). The book teaches the attack first (ethical-hacking "know your enemy") so the reader understands why each defense matters, framing SQL injection as the entry point to the broader OWASP Top 10 and to information security as a discipline.

## Structure
### Preface and front matter
Frames urgency with cited statistics: an attack every 39 seconds on average, 30,000 websites hacked daily, 75 records stolen per second, and Akamai's claim that SQL injection is 65.1% of all web-app attacks. Defines two audiences (developers wanting security skills, and security practitioners) and lists the exact toolchain: Android Studio + SDK API Level 30, Apache Tomcat 9.0, MySQL 8.0, JDK 14.0.1, Eclipse for Enterprise Java. GitHub repo and Code-in-Action videos provided.

### Chapter 1 - Structured Query Language for SQL Injection (theory)
Relational vs non-relational (network, graph, object-oriented, document) DBMS models. Compares MySQL, SQLite, Oracle, MSSQL with their comment syntaxes and default databases. Walks SELECT/INSERT/CREATE/DROP/ALTER. Introduces code injection as a string-parser failure and gives three security-by-design rules: no unnecessary special characters, whitelist suspicious commands, never give the user carte blanche.

### Chapter 2 - Manipulating SQL: Exploiting SQL Injection (theory)
Core attack catalog. Enabling characters (quote, semicolon, comment). Shows the vulnerable PHP query-construction pattern. UNION-based information gathering and schema extraction across MySQL information_schema, MSSQL master..sysdatabases/sysobjects with the full xtype value table, and Oracle's v$database/global_name/DUAL/all_tables. Database dumping, MD5 hash cracking, tautology auth bypass (' OR '1=1'--), and blind SQLi: Boolean-based, time-based (SLEEP/BENCHMARK, WAITFOR DELAY/TIME, DBMS_LOCK.SLEEP, UTL_INADDR), SUBSTRING inference, and splitting-and-balancing. Closes with NoSQL injection against MongoDB using the $ne operator.

### Chapter 3 - Setting Up the Environment (practice)
Builds the lab: VirtualBox (or VMware), Kali Linux client VM (1024 MB RAM, 8 GB disk minimum), and the OWASP Broken Web Applications (BWA) VM (1.8 GB download, 37 apps, discontinued 2015) set to Host-Only networking. Covers the offensive tools (OWASP ZAP, Burp Suite, sqlmap, SQLninja) and the apt-get install commands. Sets up Android Studio AVD (Pixel 2, Android 10), Tomcat, MySQL Community + Workbench, MySQL JDBC connector, and Eclipse for the mobile/IoT web-service scenarios. Mentions OWASP IoTGoat.

### Chapter 4 - Attacking Web, Mobile, and IoT Applications (practice, the core)
Step-by-step guided exploitation. Mutillidae II: client-side control bypass via GET params, tautology data extraction, 7-column UNION @@VERSION discovery, INSERT-statement subquery exfiltration with LIMIT 1. Magical Code Injection Rainbow SQLol challenges 0-5: tautology, schema enumeration, CHAR(27) quote-filter bypass, LIMIT/OFFSET, ExtractValue() error-based extraction, and full binary-search blind inference using ASCII(SUBSTRING()). Peruggia: login bypass as inference oracle and pic_id UNION injection. Automated: OWASP ZAP spider/scan/fuzz and sqlmap (--dbs, --tables, --dump, --data for POST, built-in hash cracking). Mobile (SOAP/getUser) and IoT (status-field subquery) attacks.

### Chapter 5 - Preventing SQL Injection with Defensive Solutions
Zero-trust framing of user input. Code-level: input validation (blacklist vs whitelist with Java, PHP preg_match, ASP.NET RegularExpressionValidator examples); parameterized queries (JDBC PreparedStatement, PHP PDO bindParam, ADO.NET SqlClient/OracleClient); character encoding/escaping (mysql_real_escape_string, ESCAPE clause, wildcard % handling); secure coding (OWASP SAMM, abstraction layers, SHA-2 over MD5, data masking, stored procedures with least privilege). Platform-level: WAFs (ModSecurity, UrlScan, OWASP Stinger), application IDS, database firewalls, AES-256 encryption with off-box key storage, patching, least privilege, NAC, robots.txt anti-Google-hacking.

### Chapter 6 - Putting It All Together + Assessments + back matter
Retrospective synthesis of all attack techniques and defenses. Places SQL/NoSQL injection at #1 of the OWASP Top 10 (2017), cites real cases (1.2 billion credentials stolen by a Russian gang per NYT 2014; Starbucks accounting DB SQLi per PortSwigger 2019), and discusses EternalBlue/SMB/NSA as an undisclosed-vulnerability cautionary tale. Lists and describes all ten OWASP Top 10 categories and the vulnerability lifecycle (discover, test for false positives and impact, remediate or accept risk). Assessments give answers to every chapter's questions.

## Core ideas
- SQL injection is an application-layer bug, not a database bug: the database only ever evaluates the SQL string it is handed, so the failure is the application concatenating untrusted input into that string (String query = "...WHERE username='" + user_id + "'...").
- Defense must be simultaneous and layered, never singular: the book repeatedly demonstrates that any one control (client-side JS checks, single-quote filtering, even parameterized queries that call vulnerable stored procedures) can be bypassed, so only stacked code-level plus platform-level defenses approach safety.
- Teach the attack to understand the defense: the authors deliberately put two full offensive chapters before the defensive chapter, justified as the ethical-hacking 'know your enemy' principle so each countermeasure is motivated by a concrete bypass the reader already executed.
- The SELECT statement is the prime injection enabler because it is the most common application query, and UNION is the single most powerful primitive for turning a SELECT into arbitrary database discovery and dumping.
- Blind SQL injection is the realistic default, not the exception: most production apps do not echo query output, so Boolean-based inference, time-based delays, and error-channel extraction (ExtractValue) are the working techniques, and binary search over ASCII values makes character-by-character extraction tractable.
- DBMS fingerprinting matters operationally: comment syntax, default databases, and version functions differ enough (MySQL information_schema vs MSSQL master..sysdatabases vs Oracle's compartmentalized v$database/DUAL) that an attacker must identify the engine before choosing payloads.
- Whitelisting beats blacklisting as a validation philosophy because blacklists fail open against novel encodings and newly discovered attacks, whereas whitelists fail closed by rejecting anything not explicitly envisioned.
- Hashing choice is a load-bearing defense: MD5 (128-bit, 32 hex digits) is broken and lets a dumped hash become a cracked password, while SHA-2 (256/512-bit) raises the cost; the WordPress and root-account examples show MD5 cracking in practice.
- Injection generalizes beyond SQL and beyond web apps: the same trust-the-input failure appears in MongoDB ($ne operator), SOAP web services, Android mobile clients, and IoT status controllers, all demonstrated against the same shared MySQL backend.
- A shared database multiplies blast radius: because OWASP BWA runs many apps on one MySQL instance, injecting one app exposes other apps' schemas (WordPress, SQLol SSN table), illustrating why least privilege and separation of duties matter.
- Encryption is only as strong as key custody: AES-256 is effectively unbreakable by brute force, but storing the key on the same server as the data defeats it, so the key must live elsewhere (e.g., the application server) so an attacker must compromise two systems.
- Vulnerability management is a three-phase lifecycle (discover, then test for false positives and real impact, then remediate or accept risk), and the practical chapter is explicitly a simulation of a security professional's assessment work, not just attack practice.
- Undisclosed vulnerabilities are more dangerous than disclosed ones: the EternalBlue/NSA example argues that full public disclosure, even though it temporarily helps attackers, is safer than letting a bug stay secretly exploitable for ~5 years.

## Techniques and methods
- Tautology authentication bypass: insert ' OR 1=1 -- - (or x' OR '1=1'--) into a login field so the WHERE clause is always true; comment sequence strips the trailing app-supplied quote.
- UNION-based column discovery: trial-and-error padding such as ' UNION SELECT 1,@@VERSION,3,4,5,6,7 -- - to match the original column count (7 here) and surface output in the displayed columns (2,3,4).
- Schema enumeration: MySQL SELECT table_schema,table_name FROM information_schema.tables / information_schema.columns; MSSQL SELECT name FROM master..sysdatabases and ...sysobjects WHERE xtype='U'; Oracle SELECT table_name,owner FROM all_tables and SELECT column_name FROM all_tab_columns.
- Error-message DBMS fingerprinting: submit a lone single quote to trigger a verbose SQL error revealing engine, table names, and query structure.
- INSERT-statement exfiltration via subquery: payload test','test',(SELECT password FROM mysql.user WHERE user='root') LIMIT 1))-- - smuggles a SELECT into a registration form not meant to return data.
- Quote-filter bypass with CHAR(): CHAR(27) UNION SELECT 1 -- - reconstructs the stripped single quote at runtime (CHAR maps a number to its ASCII character).
- Error-based extraction with ExtractValue('randomxml', CONCAT('=', (SELECT ... LIMIT 1 OFFSET n))) to leak query results inside an XPATH syntax error.
- Boolean binary-search blind inference: ' OR ASCII(SUBSTRING((SELECT NAME FROM SSN LIMIT 1 OFFSET 0),1,1)) >= 128 -- -, halving the 0-255 ASCII range each iteration (128 -> 64 -> 96 -> 80 -> 72 -> 76 -> 72) to recover 'H'.
- Time-based blind injection: MySQL SLEEP(15) and BENCHMARK(10000, SELECT @@VERSION); MSSQL WAITFOR DELAY(0:0:15) / WAITFOR TIME(9:0:15); Oracle BEGIN DBMS_LOCK.SLEEP(15); END; and heavy-join / UTL_INADDR.get_host_name tricks.
- Combined time-and-Boolean: SELECT IF SUBSTRING(fieldname,1,1)='x' SLEEP(15) so the signal is response latency.
- Splitting and balancing: replace id=3 with id=2+1 or id=3+(SELECT 2-2), and 'Jonathan' with 'Jo'||'nathan', to inject balanced equivalent subqueries.
- NoSQL injection: GET ...password[%24ne]= becomes {"password":{"$ne":""}} in MongoDB, making find() always succeed; works as JSON or urlencoded POST body.
- sqlmap workflow: sqlmap -u URL (detect) -> --dbs -> --tables -D peruggia -> --dump -D peruggia -T users (with built-in hash cracking); --data for POST forms; results saved to ~/.sqlmap/output as CSV.
- OWASP ZAP automated workflow: Automated Scan = Spider (crawl) + Scanner (payload fuzzing) -> Alerts; plus Manual Explore proxy (localhost:8080) and the Fuzzer module with custom SQLi wordlists.
- Parameterized queries: JDBC PreparedStatement with ? placeholders and ps.setString(1,user); PHP PDO prepare + bindParam(1,$user,PDO::PARAM_STR); ADO.NET cmd.Parameters.Add('@user', SqlDbType.NVarChar).
- Input validation by regex: Java s.matches("[[A-Z][a-zA-Z]*]"), PHP preg_match, ASP.NET RegularExpressionValidator ValidationExpression='[A-Z][a-zA-Z]*'.
- Character escaping: mysql_real_escape_string(), doubling quotes ('' ), backslash-escaping, and the SQL Server/Oracle ESCAPE clause for LIKE wildcards (LIKE 'a\%' ESCAPE '\').
- Platform defenses: WAF filters (ModSecurity for Apache, UrlScan for IIS), passive-mode WAF as application IDS, database firewall proxy with whitelist rules, AES-256 with off-box key, patching, least privilege, NAC, robots.txt (User-agent: * / Disallow: /).

## Curriculum fit
For a security-research reading list this is foundational rather than advanced: it codifies the canonical SQLi taxonomy (UNION, error-based, Boolean/time-based blind, splitting-and-balancing, NoSQL) and the matching defense matrix, which is useful as a shared vocabulary and a teaching scaffold but offers nothing novel to an ICS/OT specialist already publishing CVEs. Its real value to this curriculum is methodological and pedagogical: the explicit attack-before-defense structure mirrors NuClide's 'know your enemy' verify-the-finding discipline, and the three-phase vulnerability lifecycle (discover -> test for false positives and real impact -> remediate or accept risk) is a clean restatement of the principle that a scan produces candidates while verification produces findings. The lab-build chapter (OWASP BWA, Kali, sqlmap, ZAP, AVD, Tomcat web services) is a reusable template for safe, scoped, lab-only testing, reinforcing the restraint ethic. For the creativity/leadership/agentic-AI threads it is thin, with two transferable hooks: chain-thinking is demonstrated concretely (a shared MySQL instance turns one app's injection into cross-app schema exposure, and the Starbucks case required chaining SQLi with other weaknesses), and the NoSQL/MongoDB $ne and SOAP/IoT sections generalize injection as a trust-the-input failure that maps directly onto modern LLM/agent prompt-injection and tool-input-injection threat modeling. Best slotted early as a refresher and as source material for explaining injection lineage to non-specialist stakeholders; pair it with primary OWASP Top 10 docs and PortSwigger Web Security Academy for depth the book intentionally omits.
