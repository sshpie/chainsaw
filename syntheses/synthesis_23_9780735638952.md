# Windows 7 Resource Kit

ISBN: 9780735638952  |  Book #23

## One-liner
The authoritative ~1,500-page Microsoft Press operations manual for deploying, managing, securing, and troubleshooting Windows 7 across enterprise fleets, organized as a layered defense-in-depth platform rather than a feature catalog.

## Thesis
Windows 7 is presented as an operating system engineered to be "secure by default" through defense-in-depth: every common attack vector (malware bundling, social engineering, browser exploits, network worms, physical disk theft) is met by multiple independent layers so that defeating one layer does not compromise the host. The book's purpose is to give experienced IT professionals in AD DS environments the architectural understanding and task-based procedures to deploy at scale (MDT 2010, WIM, USMT), centrally manage via Group Policy and PowerShell, and harden via UAC, AppLocker, BitLocker, Windows Firewall with Advanced Security, and Windows Service Hardening. Its recurring claim is that security degrades over time and through human error, so the right posture is layered, auditable, centrally-policy-driven, and least-privilege by default.

## Structure
### Part I - Overview (Ch 1-2)
Chapter 1 surveys non-security improvements (taskbar/Jump Lists/Libraries, editions matrix from Starter to Ultimate, single Install.wim keyed by product key). Chapter 2 is the load-bearing security chapter: it frames Windows 7 as defense-in-depth against four attack classes and catalogs every defense - UAC, Windows Defender, Windows Firewall, EFS, BitLocker/BitLocker To Go, plus architectural internals (Code Integrity, Windows Resource Protection, Kernel Patch Protection, mandatory 64-bit driver signing, Windows Service Hardening, DEP, ASLR, CNG, new credential-provider logon architecture, RMS, Multiple Local GPOs, NAP client, WS-Management).

### Part II - Deployment (Ch 3-12)
Image-based deployment platform: WIM file format, Unattend.xml answer files and the 7 configuration passes, Windows SIM, Sysprep (/generalize /oobe /audit), Windows PE 3.0, DISM (replacing Pkgmgr/PEImg/Intlcfg), ImageX, BCDboot, DiskPart. WDS (PXE/TFTP, Single Instance Storage), MDT 2010 Lite Touch (deployment shares, task sequences, CustomSettings.ini, MDT database), thick/thin/hybrid image strategies, USMT 4.0 ScanState/LoadState with hard-link migration, application packaging (msiexec /qn ALLUSERS=2, repackaging), and Volume Activation (KMS vs MAK, 25-client threshold, 180-day reactivation).

### Part III - Desktop Management (Ch 13-20)
PowerShell 2.0 (cmdlets, pipeline, modules, remoting via WS-Management, execution-policy Restricted/AllSigned/RemoteSigned/Unrestricted/Bypass). Group Policy with ADMX/ADML central store, Starter GPOs (EC/SSLF), Multiple Local GPOs. Disks/file systems: MBR vs GPT, VHD boot, Defrag, Backup and Restore, ReadyBoost, and the deep BitLocker/EFS chapter (FVEK/VMK, AES+Elephant Diffuser, TPM modes, Manage-bde, recovery, data recovery agents, symbolic links). Internet Explorer 8: InPrivate, SmartScreen, Protected Mode/Mandatory Integrity Control, IDN/Punycode anti-spoofing, security zones, 1,300+ Group Policy settings.

### Part IV - Desktop Maintenance (Ch 21-24)
Eventing infrastructure and Event Viewer, performance monitoring, Remote Assistance, software updates (WSUS, BITS, Automatic Updates), and the client-protection chapter: UAC (Admin Approval Mode, two access tokens, manifest levels asInvoker/highestAvailable/requireAdministrator, virtualization to VirtualStore, secure desktop, Token Elevation Types, audit Event IDs 4648/4624/4688), AppLocker (hash/path/publisher rules, audit-only mode, Application Identity service, vs Software Restriction Policies), Windows Defender (real-time agents, SpyNet basic/advanced, alert levels), NAP (SHA/SHV health enforcement), and Forefront/FCS for enterprise.

### Part V - Networking (Ch 25-28)
Core networking and wireless, then Windows Firewall with Advanced Security and IPsec: Windows Filtering Platform (BFE/GFE/callouts), boot-time/persistent/dynamic filters, the always-on stealth feature (blocks outbound TCP RST and ICMP unreachable to defeat fingerprinting), Windows Service Hardening (per-service SIDs S-1-5-80, sc sidtype, write-restricted tokens, service restriction rules), multiple active firewall profiles, allow-if-secure and authenticated-bypass rules. Chapter 27 covers remote access: IKEv2/MOBIKE/VPN Reconnect, DirectAccess (IPv6 with Teredo/6to4/IP-HTTPS, IPsec, PKI, NAP), BranchCache (Hosted vs Distributed Cache), RDP, and IPv6 transition.

### Part VI - Troubleshooting (Ch 29-31)
Systematic troubleshooting of startup (the POST -> Boot Manager -> Boot Loader -> kernel -> logon sequence, BCD/BCDEdit replacing Boot.ini, WinRE/Startup Repair auto-installed in Windows 7, control sets and LastKnownGood, Start/Type registry values for driver loading), hardware (Windows Memory Diagnostic, Reliability Monitor), networking diagnostics, and interpreting Stop messages (bug-check codes).

## Core ideas
- Defense-in-depth is the organizing philosophy, not a chapter: each of the four malware vectors (bundling/social engineering, browser exploit, network worm, physical theft) is explicitly mapped to four independent defensive layers, so single-layer failure or human misconfiguration does not yield compromise.
- Least privilege by default: UAC gives even administrators a standard-user token at logon and only elevates a full-administrator token after explicit consent on the secure desktop, inverting the historical Windows assumption that everything runs as admin.
- The book repeatedly argues against a setuid/sudo-style 'authorize once' model (Aaron Margosis sidebar): silent elevation would simply migrate the whole ecosystem to silent elevation and re-create the malware problem, so UAC deliberately refuses a bypass.
- BitLocker's two-key architecture (256-bit FVEK encrypting the volume, 256-bit VMK encrypting the FVEK, VMK sealed to the TPM/PCRs) plus the message-authenticity-check on BCD means an attacker who modifies any early boot file fails the PCR comparison and the TPM withholds the key - tamper-evidence enforced cryptographically.
- Image-based deployment (one WIM, edition selected by product key, answer file driven across 7 configuration passes) replaces the old per-SKU media model and makes the deployment artifact itself hardware-agnostic.
- Windows Service Hardening enforces least privilege on services via per-service SIDs (S-1-5-80-{SHA1 of service name}) and write-restricted tokens, plus a firewall policy bound to the service SID that the administrator cannot relax - a sandbox the worm cannot escape even after exploiting the service.
- The firewall stealth feature is an always-on, non-configurable anti-reconnaissance measure: it suppresses outbound TCP RST and ICMP port/protocol-unreachable so a remote scanner cannot distinguish a closed port from a firewalled-but-listening port.
- AppLocker's publisher rules move application control from brittle hashes/paths to cryptographic signature metadata, enabling rules like 'allow Microsoft Office signed and version >= 12.0.0.0' that survive updates - and the audit-only mode is mandatory practice before enforcement because one bad rule can lock thousands of users out.
- Internet Explorer Protected Mode is defense-in-depth for the browser: Mandatory Integrity Control runs IE as a Low-integrity process that can write only to Low-integrity locations, with broker processes (IEUser.exe, IEInstal.exe) for any escalation - so a browser compromise cannot silently plant a startup keylogger.
- DirectAccess reframes remote access: instead of a user-initiated VPN, the managed laptop is always-on-corpnet over IPv6 (Teredo/6to4/IP-HTTPS tunneling) with IPsec, which means IT can patch and apply Group Policy to mobile machines that previously went weeks unmanaged - a security-via-manageability argument.
- 64-bit Windows is structurally more secure than 32-bit because three protections are mandatory there: Kernel Patch Protection (PatchGuard), hardware DEP, and required kernel-mode driver signing.
- Verification/auditing is treated as a first-class countermeasure: Code Integrity is a detective control, UAC elevation and AppLocker actions write specific Event IDs, and the book repeatedly pairs preventive controls with detective (auditing) and reactive (backup/System Restore) ones.
- Security degrades over time through operational drift (a tech disables a setting while troubleshooting, a mobile machine misses updates), so the recommended posture is centralized Group Policy, MBSA scanning, and policy that re-asserts itself rather than one-time hardening.

## Techniques and methods
- Defense-in-depth layer-mapping: for each attack vector enumerate the independent layers (e.g., worm = Windows Firewall + Automatic Updates + Windows Service Hardening + UAC limited privilege).
- UAC application manifest requested-execution levels: asInvoker / highestAvailable / requireAdministrator, plus heuristic installer detection on filenames containing 'install/setup/update'.
- UAC virtualization redirect: writes to %ProgramFiles%, %WinDir%, HKLM\Software are silently redirected to %LocalAppData%\VirtualStore for legacy apps.
- BitLocker startup phases: system-integrity verification (PCR measurements) -> optional user auth (PIN/USB) -> VMK retrieval from TPM -> OS-loader validation via BCD MAC -> FVEK decryption.
- manage-bde command pattern: manage-bde -status; manage-bde -on C: -RecoveryKey Y: -RecoveryPassword; manage-bde -off C:; recovery via repair-bde from WinRE.
- Secure BitLocker decommission via WMI: Win32_EncryptableVolume.GetKeyProtectors / ProtectKeyWithNumericalPassword / DeleteKeyProtector then Win32_TPM.Clear.
- AppLocker rule generation: create default rules first (Windows folder, Program Files, admins), then Automatically Generate Rules from a reference machine, default to publisher rules with hash fallback, run Audit Only, then Enforce.
- Service SID hardening: sc sidtype <service> restricted|unrestricted|none; query with sc qsidtype; inspect firewall triggers with sc qtriggerinfo <service>.
- Firewall rule taxonomy: inbound/outbound x allow/block/allow-if-secure x authenticated-bypass, scoped by the logical-AND of filtering conditions (protocol, ports, IP scope, profile, interface type, program, service).
- IE Protected Mode broker model: IEUser.exe (User Broker for saving files outside Low-integrity) and IEInstal.exe (Admin Broker for ActiveX installs); compatibility layer redirects writes to Temporary Internet Files\Virtualized.
- PowerShell remoting and execution-policy hardening: Set-ExecutionPolicy RemoteSigned (Microsoft-recommended), Enable-PSRemoting over WS-Management, Get-Help about_signing.
- VPN Reconnect protocol stack: IPsec tunnel-mode ESP + IKEv2 for key negotiation + MOBIKE to swap tunnel endpoints when the reachable IP changes (~500 bytes vs 4000-8000 for full IKEv2 renegotiation).
- Startup troubleshooting via BCDEdit/Bootrec and the {bootmgr}/{current}/{default}/{ntldr} BCD object aliases; control-set recovery with LastKnownGood.
- UAC privilege-elevation auditing: enable Audit Process Tracking + Audit Privilege Use, then filter Security log for Event ID 4688 and search 'TokenElevationTypeFull'.

## Memorable
- KMS specifics: TCP port 1688, DNS SRV record, 25-client activation threshold for clients, 180-day reactivation window, 30-day CMID cache, 30-day grace, rearm up to 3 times (120 days).
- BitLocker recovery password is exactly 48 digits, entered with function keys F1-F10 at the recovery screen because localized keyboard support is unavailable that early in boot; sample from text: 460559-421212-096877-553201-389444-471801-362252-086284.
- Default BitLocker cipher is 128-bit AES with Diffuser (Group Policy can set 256-bit AES with Diffuser, 128-bit AES, or 256-bit AES); FVEK and VMK are both 256-bit; FVE Filter Driver is Fvevol.sys.
- Service SID format: S-1-5-80-{SHA1 hash of short service name}; LocalSystem services are 'omnipotent' and unprotected by WSH - only NetworkService/LocalService services are sandboxed.
- Firewall stealth blocks outbound TCP RST and replies ICMPv4 type3/code3 (port unreachable) / code2 (protocol unreachable) and ICMPv6 type1 so scanners cannot fingerprint closed vs blocked ports.
- DirectAccess perimeter firewall exceptions: UDP 3544 (Teredo), IPv4 protocol 41 (6to4), TCP 443 (IP-HTTPS); for IPv6 Internet: ICMPv6, UDP 500, IPv4 protocol 50.
- Mandatory Integrity Control levels: High (admin, can write Program Files/HKLM), Medium (user, default for unlabeled objects), Low (untrusted, IE Protected Mode writes only to Temporary Internet Files\Low).
- IE8 SmartScreen sends URLs to https://urs.microsoft.com over TCP 443, ~8 KB per lookup, strips query strings (e.g. sends bing.com/search not the search term); the 3Sharp study had IE7 Phishing Filter catch ~9 of 10 phishing sites with 0 false positives on 500 good sites.
- UAC audit Event IDs: 4648 precedes 4624 with Consent.exe in the path; Token Elevation Types 1 (default, no prompt), 2 (full, the only type that prompts), 3 (limited).
- Windows Easy Transfer Cable moves ~20 GB/hour; Defrag default runs 1 A.M. Wednesday with a 64 MB fragment threshold and is SSD/TRIM-aware.
- Named CVE-class examples used as teaching cases: CodeRed worm (Index Server ISAPI buffer overflow, the canonical DEP example) and the Blaster worm (RPC service abuse, the canonical Windows Service Hardening example).
- PowerShell execution-policy ladder: Restricted (default, no scripts) / AllSigned / RemoteSigned (Microsoft-recommended) / Unrestricted / Bypass.
- Aaron Margosis quote on why UAC has no bypass: 'If it were possible to mark an application to run with silently elevated privileges... They'd all be marked to elevate silently.'
- Driver Start registry values: 0 Boot, 1 System, 2 Auto load, 3 Load on demand, 4 Disabled, 5 Delayed start (new in Vista).

## Curriculum fit
For a security-research reading list this is a primary-source mental model of a Windows endpoint's defensive surface, which is exactly the attack surface -style assessment work enumerates. It documents, from the vendor's own engineers, where the trust boundaries sit (MIC integrity levels, service SIDs, the TPM/PCR seal, the firewall stealth fingerprint-suppression, AppLocker bypass classes via path rules), which is more useful to an attacker/defender than any CVE list because it explains the assumptions each control makes and therefore where it fails - the same 'why built this way, what assumption, where does it fail' structural lens in the methodology. The UAC/AppLocker/WSH chapters are directly relevant to privilege-escalation and application-control-bypass research; the BitLocker chapter is a clean worked example of key-hierarchy and tamper-evidence design worth modeling against modern disk-encryption attacks (cold-boot, DMA, Bitlocker-without-TPM USB-key risk the book itself flags). On the leadership and creativity axis, the book is a strong artifact of technical-writing craft: the 'Direct from the Source' engineer sidebars are a model of authoritative-yet-honest explanation (Margosis on refusing a UAC bypass, the boot-time-filtering walkthrough), and its consistent preventive/detective/reactive countermeasure framing is a reusable mental scaffold for risk communication to a CISO. For agentic-AI research the relevance is more analogical than direct: the defense-in-depth layering, the deliberate refusal to build a 'silent elevate once' shortcut, the per-service least-privilege sandbox with a policy the actor cannot relax, and the audit-only-before-enforce discipline are all design patterns that map cleanly onto sandboxing and capability-scoping for autonomous agents. The chapter on WS-Management/PowerShell remoting and the central-policy model also prefigures fleet-orchestration concerns. It is dated (Windows 7, 2009) so it is not a current-threat reference, but as a reasoning-pattern and trust-boundary source it earns a place as the canonical Windows-internals-for-operators entry on the list.
