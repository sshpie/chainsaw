# 53. The IDA Pro Book

## What this book actually is

Chris Eagle's *The IDA Pro Book* (2nd ed., No Starch, IDA 5.x era) is the canonical operator's manual for IDA Pro, the disassembler that anchored binary reverse engineering for two decades. It is not an exploit cookbook and not an assembly primer; it teaches one thing exhaustively: how to drive IDA to turn an opaque compiled binary into a richly annotated, navigable map of what the code does. The extract in `books/53` carries the complete detailed table of contents (26 chapters plus appendices), the full prose of Chapter 12 (FLIRT/FLAIR), and a comprehensive function-and-concept index; together these locate every technique precisely.

## The conceptual spine (Part I, ch 1-3)

Chapter 1 is the load-bearing theory: disassembly is genuinely hard, and the two strategies are both flawed. **Linear sweep** decodes bytes sequentially and is fooled by data embedded in code; **recursive descent** follows control flow and is blind to indirect or dynamically computed jump targets (see the index entries at line 1554, "recursive descent failure on return"). IDA blends both and leans on the analyst's judgment. Chapter 2 surveys the classification/summary/inspection toolchain (file, nm, ldd, objdump, otool, strings) that frames a target before IDA opens it.

## Basic and advanced usage (Parts II-III, ch 4-14)

The middle chapters teach the database-as-workspace model: the IDB, not the binary, is what you build. Disassembly displays, navigation, stack-frame and calling-convention reading (ch 6), naming and commenting, converting data to code, and crucially **data types and structures** (ch 8) including a C++ reversing primer (this-pointer, vtables, name mangling, RTTI, inheritance). Cross-references and graphing (ch 9) make control and data flow visible. Chapter 12, the one chapter rendered in full here, is **FLIRT/FLAIR library recognition**: signature pattern-matching that marks and renames known library functions in statically linked binaries so analysis time concentrates on the application's unique code. The chapter walks the full FLAIR pipeline: acquire the exact static lib (file/strings to pin the OS/distro), run the format-appropriate parser (plb/pcf/pelf) to make a `.pat`, run `sigmake` to produce a `.sig`, resolve collisions via the `.exc` exclusions file, install to `<IDADIR>/sig`, plus startup signatures that fingerprint the compiler. Chapter 14 covers patching binaries and IDA's output/patch-generation files.

## Extending IDA (Part IV, ch 15-19)

This is the platform argument: IDA is programmable at every layer. **IDC** (ch 15) is the built-in scripting language with a rich API for reading/modifying the database, walking cross-references, and enumerating functions and instructions. The **SDK** (ch 16) exposes netnodes, datatypes, and iteration over the database in C++. The **plug-in architecture** (ch 17), **loader modules** (ch 18, including a worked pcap loader), and **processor modules** (ch 19, building a disassembler for Python byte code via the analyzer/emulator/outputter triad) let you teach IDA any file format or instruction set. IDAPython (ch 23) is the practical successor to IDC.

## Real-world applications (Part V, ch 20-23)

Where the craft pays off for . **Compiler variations** (ch 20: jump tables, RTTI, locating main, debug-vs-release, calling conventions). **Obfuscated-code analysis** (ch 21): anti-static techniques (disassembly desynchronization, dynamically computed targets, import-function obfuscation), anti-dynamic techniques (VM/instrumentation/debugger detection), and static plus emulation-oriented de-obfuscation. **Vulnerability analysis** (ch 22): discovering new bugs, after-the-fact discovery by binary-diffing patches, the exploit-development support role (stack-frame breakdown, locating instruction sequences/ROP gadgets, finding useful virtual addresses), and shellcode analysis.

## The debugger (Part VI, ch 24-26)

IDA's integrated debugger closes the static/dynamic loop: breakpoints, tracing, watches, scripting debugger actions, and disassembler/debugger integration for unpacking (simple decryption/decompression loops, import-table reconstruction, hiding the debugger from anti-analysis checks). Remote and Linux/OSX debugging round it out. Read 53 when the artifact is the binary and source has run out.
