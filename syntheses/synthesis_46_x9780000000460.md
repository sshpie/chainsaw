# 46. Complete Guide to Shodan: Collect, Analyze, Visualize

## What book 46 actually teaches

This is John Matherly's own short, dense guide to the search engine he built (Leanpub, 2016). It is not a third-party tutorial; it is the source-of-truth on how Shodan collects and exposes data, which is precisely why it matters to our Step 0 harvest. Read it to understand the mechanism we are driving, not for offensive tradecraft (it has almost none).

**All About the Data.** The atomic unit is the *banner* - the textual service description (HTTP headers, a Telnet login screen, a Siemens S7 firmware dump). Critically, Shodan indexes banners, not hosts: one IP with many services returns many separate results. Metadata (geo, hostname, OS, ASN, ISP) rides alongside (Appendix A is the full schema). Crawlers run 24/7 from globally distributed nodes (US, China, Iceland, France, Taiwan, etc.) to avoid country-block bias, and the core algorithm is deliberately randomized: pick a random IPv4, a random port from the known set, grab the banner, repeat - uniform population sampling, not incremental range scanning. SSL gets deep treatment: ssl.versions (explicit per-version probing, leading-dash means unsupported), ssl.chain (full PEM chain), dhparams (Logjam), and vuln tagging (Heartbleed CVE-2014-0160, FREAK CVE-2015-0204, with a leading ! meaning not-vulnerable). Two advanced techniques: **web components** (http.components fingerprints Drupal/jQuery/PHP via headers+HTML, queryable by http.component filter and facet) and **cascading** (a banner that leaks peers - DHT, Bitcoin, Elastic nodes - triggers child banner-grabs, tracked via _shodan.id and _shodan.options.referrer).

**Web Interfaces & Search Query.** Default search reads only the main banner text (searching "Google" finds Google Search Appliances, not Google's netblock), terms are implicitly ANDed, and results default to the last 30 days. Metadata requires *filters* (filtername:value, no space after the colon, quote values with spaces, comma for multi-value, leading minus to exclude). Key filters: product, port, net (CIDR), org, country, city, category:ics, hash:0 (empty banner), has_screenshot. *Reports* generate free aggregate charts (a snapshot you can keep to track change over time). The non-default-port example (product:openssh -port:22) is the load-bearing security lesson: obscurity is measurable - ports cluster predictably at 2222/5000, and an Australian ISP exposed ~54k boxes with identical SSH keys.

**External Tools (CLI).** The shodan CLI ships with the Python lib. Core verbs: count, download (--limit -1 to get all, save then process), parse (--fields ip_str,port,org to CSV), host, search, stats --facets, stream (--datadir, --ports, --limit), convert (to kml/csv), honeyscore, info (credits). The discipline: download-then-parse so you do not re-spend query credits on a search you already ran.

**Developer API.** REST + Streaming. Three credit types: query credits (filtered search or page>1), scan credits (on-demand async scan, results arrive via host lookup / search / stream), and network-alert IP limits (max 100 alerts). **Facets** are the analytical heart - aggregate a field (port:22 faceted on ssh.fingerprint reveals duplicate-key populations); facets are API/CLI-only. search_cursor() loops all results but disallows facets; minify=False returns truncated large fields (html). host(ip, history=True) returns full banner history. The MongoDB worked example downloads all product:mongodb banners and parses them to total exposed data (1.8 PB) and top database names - population-scale data-exposure analysis from schema/metadata, our exact methodology.

**ICS & Honeypots.** ~2M+ ICS devices online (Project SHINE); category:ics minus -http -html -ssh -ident isolates raw unauthenticated protocols (Fox/Niagara dominant, then BACnet, Modbus, S7). Raw ICS protocols need no auth - reachability is read/write. The honeypot chapter is the discriminator we still use: Conpot defaults (serial 88111222, PLC name, plant id), the 30%-duplicate-serial heuristic, too-many-services (>10 ports = suspicious), implausible cloud hosting (a PLC in EC2), and indexed banner history that outlives the bug-fix; honeyscore and the honeypot tag operationalize it.
