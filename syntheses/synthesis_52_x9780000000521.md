# 52. Practical Malware Analysis

Sikorski and Honig (Mandiant, 2012) is the canonical hands-on malware-analysis text, built around incident response: the job is to determine what a suspect binary does, find every infected host, and produce signatures to detect and contain it. Its organizing idea is the four-quadrant method - static vs dynamic crossed with basic vs advanced - and the discipline of escalating quadrants only as cheaper ones run dry, never opening with the disassembler.

Part 1 (Basic Analysis) is the cheap-reversible layer  should reach for first. Chapter 1 (Basic Static): antivirus/VirusTotal as a first pass, MD5/SHA-1 hashing as a fingerprint, strings extraction, and the central skill of reading the Windows PE file format - linked libraries and imported functions. Capability is inferred from API names alone: URLDownloadToFile implies a downloader, WS2_32/WSock32 implies networking, Ntdll or SeDebugPrivilege implies process manipulation. A near-empty import/string table that shows only LoadLibrary+GetProcAddress is the packing/obfuscation tell (PEiD, UPX -d). Chapter 2 is the safe VM lab. Chapter 3 (Basic Dynamic) is detonation: procmon + Process Explorer + Regshot for host artifacts, and the fake-network stack - ApateDNS (spoof DNS, NXDOMAIN trick to pull more domains), Netcat listeners, Wireshark Follow-TCP-Stream, and INetSim simulating HTTP/DNS/FTP/etc so the sample keeps running and reveals its beacon.

Part 2 (Advanced Static) and Part 3 (Advanced Dynamic) are the x86 disassembly path: a crash course in registers/stack, IDA Pro (renaming, comments, IDC/IDAPython scripting), recognizing C constructs (if/loops/switch/structs/arrays) and C++ vtables in assembly, the Windows API surface, then OllyDbg (breakpoints, tracing, patching) and WinDbg for kernel/rootkit debugging. These chapters assume comfort with assembly that the book does not fully teach.

Part 4 (Malware Functionality) is the behavioral catalog  can use as a hypothesis generator: backdoors, RATs, botnets, downloaders, launchers, credential stealers (GINA, hash dumping, keyloggers), persistence (registry Run keys, trojanized binaries, DLL load-order hijacking), privilege escalation, and user-mode rootkits (IAT/inline hooking). Chapter 12 (Covert Launching) details process injection - DLL injection via LoadLibrary, process replacement, hook injection, Detours, APC injection - and the VirtualAllocEx/WriteProcessMemory pair that powers it. Chapter 13 (Data Encoding) covers XOR loops (brute-forcing single-byte keys), Base64 variants, and recognizing standard crypto.

Chapter 14 (Malware-Focused Network Signatures) is the most -relevant chapter and the reason this card sits in the defensive lobe. It argues content-based indicators outlast IPs/domains (cheap for an attacker to rotate), walks Snort rule construction (header, content with |0d 0a| hex notation, payload vs nonpayload options like flow/dsize, pcre), and uses a real Emerging Threats FakeAV User-Agent rule (Wefa7e, Wee6a3) to teach the load-bearing lesson: a sample size of one or two yields an overfit signature. Cross-sample across multiple hosts and multiple runs to separate random-seeded fields, host-derived fields, and truly static content - or you write a confident, reproducible, wrong rule. The Danger-of-Overanalysis hierarchy (surface -> communication-method coverage -> operational replication -> full code coverage) tells you when to stop. Crucially, the OPSEC section maps directly onto our passiveV2/restraint ethic: investigating an attacker's domain/IP can tip the operator (canary domains, anomalous DNS resolutions, search-crawler triggers), so use indirection, passive-DNS, and consolidated whois services rather than naive direct lookups.

Part 5 (Anti-Reverse-Engineering) is the arms-race half: anti-disassembly (jump-with-same-target, impossible disassembly, the call/pop pointer trick that fools flow-oriented disassemblers), anti-debugging (IsDebuggerPresent, PEB checks, timing via rdtsc), anti-VM (Red Pill, No Pill, VMware artifacts), and packers/unpacking with a step-by-step OllyDump approach. Part 6 covers shellcode analysis (position-independent code, manual symbol resolution via PEB-walking and hashed exports - the same primitives our shellcode work uses), C++, and 64-bit differences. The recurring thesis: analysis is cat-and-mouse, the sample is actively deceptive, and verification through cross-sampling and detonation is the load-bearing stage.
