# 48. Pentesting APIs and Cloud Applications

## What this book is

This is not a trade book but eLearnSecurity's WAPTXv2 Section 01, Module 14 (Caendra Inc., 2020) - a 140-slide training module, terse and lab-driven. It teaches the API and cloud slice of web-app pentesting in five sections. Read it for the concrete recipe, not for breadth; it deliberately defers auth/SSO and pure-HTTP web attacks to sibling modules.

## The five sections, in order

**14.1 Introduction to APIs.** Establishes the vocabulary: SOAP/XML (POST envelopes, SOAPAction header, WSDL contract at ?wsdl) versus REST/JSON (verb-as-meaning GET/POST/PUT/DELETE/PATCH, params in body, WADL contract, Swagger UI as the human-friendly form). Key framing: an API is a non-GUI scriptable, language-independent endpoint set, and its self-describing documentation is the recon prize.

**14.2 API Testing and Attacking.** The contract-first recon checklist: name/version, custom vs open-source, online docs, on-box docs (?wsdl/?wadl), auth-required-or-public, and the critical local-vs-public doc diff (hidden methods are the insecure ones). Tooling: SoapUI / Postman / Burp WSDLer to turn a raw WSDL/WADL into a ready method set, proxied through Burp. Then the core thesis - the API is just a transport, so tamper with everything it carries: SQLi inside a SOAP login body (' or '1'='1), XXE/SSRF via DTD (<!DOCTYPE ... SYSTEM http://attacker/ssrf>, noting modern APIs often disallow DTD), and stored XSS smuggled inside CDATA so the SOAP stays well-formed. Also: content-discovery tools still apply because some paths fall through the API router to real files (/version.txt).

**14.3 API Access Control.** APIs rarely use cookies; expect Basic, X-Api-Token headers, JWT, Bearer. The full method to test broken access control: build a working request to every endpoint, mint a token per user role, cross every request with every token AND the no-token case. Tokens inherit session-cookie weaknesses (low entropy, no invalidation, leakage, pre-generation). The Rundeck example - default adhoc OS-command-run method hidden from local docs but still live - is the recurring lesson.

**14.4 Resource Sharing (CORS).** Same-Origin Policy and how CORS relaxes it. The two load-bearing headers: Access-Control-Allow-Origin (domain/wildcard/null) and Access-Control-Allow-Credentials. The actionable finding is the AND: a server reflecting the Origin header into ACAO with ACAC:true lets an attacker-hosted script read a logged-in victim's authenticated responses (PHP one-liner reflecting $_SERVER['HTTP_ORIGIN']). Browsers block wildcard-plus-credentials, so the bypass is origin reflection or null-origin. The Hera lab is null-origin secret-token theft, framed explicitly as the CORS analog of XSS cookie theft.

**14.5 Attacking Cloud-Based Applications.** The largest section. Architecture evolution (monolithic -> tiered -> cloud-elastic -> serverless/FaaS) and why serverless changes security: no IP/port model, shared external IP, ephemeral minutes-long lifespan, state-free. Concrete labs on AWS using OWASP DVSA and ServerlessGoat:
- **S3 buckets:** misconfig as the top leak cause; s3recon (wordlist-driven, MongoDB-backed for bug-bounty scope) to find public buckets; aws-cli cp to read; signed-URL and signed-cookie temporary access as the controlled alternative.
- **Serverless event injection:** functions fire on triggers (S3 object actions, CloudWatch, API Gateway, repo changes, DB events). When user-controlled input reaches os.system("aws s3 cp {0} {1}".format(...)), it is command injection. The DVSA receipt-email walkthrough chains a world-writable S3 bucket -> uploaded payload matching the .raw/UUID naming convention -> os.system RCE -> ngrok reverse channel -> base64-encoded exfil. The payoff: lambda functions store AWS keys in environment variables, lifted via env or cat /proc/self/environ, inheriting the function's full IAM privilege.
- **GraphQL:** one endpoint, Query + Mutation only; schema/introspection/resolver/scalar terms; the security note that GraphQL has no built-in authz and returns whatever is requested, so introspection reads sensitive fields and unguarded mutations (deleteUser) execute. Google-dork /graphql.
- **FaaS** across AWS Lambda / GCF / OpenWhisk / Azure Functions, with DVFaaS as the practice ground.

## How to use it in our work

Reach here for the operational recipe when an assessed AI-infra or agent platform exposes a REST/SOAP/GraphQL API or sits on AWS S3/Lambda. The contract-first recon, the token-x-endpoint access matrix, the CORS two-header severity test, and the serverless-injection-to-IAM-key chain are directly reusable. Its dated 2020 AWS specifics (pre-IMDSv2 framing) and reliance on intentionally-vulnerable labs are the limits; verify against current cloud defaults.
