# 54. Hacking: The Art of Exploitation, 2nd Edition

Erickson's "Hacking: The Art of Exploitation, 2nd Ed" (No Starch, 2008) is the canonical from-first-principles exploitation text. It is organized in hex-numbered chapters and builds the whole mental model bottom-up rather than cataloging exploits. Reach into it when the task needs the substrate under our heavier offensive cards: how memory, registers, and the byte layer actually behave.

0x200 Programming teaches C from a hacker's perspective, then drops to the metal: x86 registers (EIP as the instruction pointer, ESP/EBP), assembly, the stack and heap, two's complement signed/unsigned integers, pointers, format specifiers, function pointers, structs, file permissions and user IDs, pseudo-random numbers. This chapter is the reason the rest is legible. It ends with a worked program (a game of chance) that gets exploited later.

0x300 Exploitation is the core. It generalizes every exploit to three steps: memory corruption, then a change in control flow, then execution of injected code. It walks stack-based buffer overflows (the classic Smashing-the-Stack lineage, Aleph1 cited), using the environment for shellcode placement and NOP sleds, heap-based overflows, overflowing function pointers, and the full format-string vulnerability family: reading arbitrary memory with %x/%s, writing arbitrary memory with %n, direct parameter access, short writes, overwriting .dtors and the Global Offset Table (GOT). The recurring lab target is a SUID-root binary, which is why this chains straight into privilege escalation.

0x400 Networking builds raw-socket programming, a simple server and web client, a tinyweb server, then layer-by-layer decoding (data-link/network/transport), raw-socket and libpcap sniffers, active sniffing and ARP redirection, TCP/IP RST hijacking and continued hijacking, denial of service (SYN flooding, Ping of Death, Teardrop, ping flooding, amplification, distributed DoS), and port scanning (stealth SYN, FIN/Xmas/Null scans, decoy spoofing, idle scanning) plus the shroud proactive defense.

0x500 Shellcode teaches writing shellcode in assembly against the Linux syscall ABI, investigating it in GDB, removing null bytes so it survives string operations, and building both port-binding and connect-back shellcode.

0x600 Countermeasures is the defender-and-bypass chapter: detection via logs and IDS/IPS, the port-31337 red flag, log-file overwriting, socket reuse (reusing the existing web request socket so no new flagged outbound TCP connection is opened, also defeating egress filters), then hardening (nonexecutable stack) and bypasses (ret2libc, returning into system() with /bin/sh, locating libc functions in GDB, ASLR randomized-stack defeat via bounce/info-leak techniques). This is the chapter for footprint and IDS-evasion reasoning during authorized work.

0x700 Cryptology covers information theory (Shannon, unconditional security, one-time pads, quantum key distribution, computational security), algorithmic complexity, symmetric vs asymmetric ciphers, RSA worked end-to-end (phi(N), key generation, why factoring 2048-bit is hard, the extended Euclidean algorithm), meet-in-the-middle key halving, MITM attacks including the SSH host-key-swap warning, password cracking against crypt()/DES salted hashes with a probability-matrix to order brute-force guessing, and a full FMS attack on WEP: the RC4 stream cipher, 24-bit IV reuse, CRC32 integrity weakness, weak-IV keystream-byte prediction, and the frequency-table key recovery (Fluhrer-Mantin-Shamir cited).

0x800 Conclusion is the Hacker Ethic argument: vulnerabilities are an inevitable product of fast software development, hackers drive the co-evolution of security, draconian laws leave more bugs for the genuinely malicious, and information itself is not a crime. The intro frames hacking as creative rule-following problem-solving (the 1,3,4,6-to-24 puzzle), finding unintended uses of a system's own laws.

Caveat for our use: it is 32-bit-era (EIP not RIP, pre-PIE, partial ASLR, no CFI/CET), so treat the mechanics as the foundational mental model rather than a copy-paste modern exploit recipe. Its enduring value is teaching us to read the byte and register layer well enough to know what a crash, a hexdump, or a malformed packet actually proves before we ever call a finding exploitable.
