# 32. Hacking Cryptography

**ISBN** 9781633439740  |  **Lobe** offensive

> The reach-for tool when crypto is in the path and you suspect the IMPLEMENTATION, not the math, is broken: a Go-coded catalog of how shipped crypto leaks via bad randomness, reused nonces, unvalidated padding, recoverable PRNG state, and non-constant-time code.

## Reach for this when

- A target hands you crypto material you can collect at population scale: many RSA public keys (run batch-GCD shared-prime), many ECDSA signatures (look for an identical r = reused nonce = total key recovery), many JWTs/session tokens, or RNG output you can sample.
- You see a server-side crypto error that distinguishes 'invalid padding' from other failures, or a measurable latency difference on decrypt/compare: CBC padding oracle or timing oracle. The discriminator IS the attack.
- An auth/MAC scheme is hand-rolled: a hash(secret||message) tag screams secret-prefix length-extension; hash(message||secret) screams collision. Only HMAC or a sponge resists both.
- Any embedded/ICS/IoT device, or any OSS crypto from an older generation, where you suspect weak entropy at key-gen time (no hardware RNG, boot-time key generation, shared firmware seed) producing shared primes or predictable nonces.
- You need to clone a PRNG to predict 'unpredictable' tokens: an LCG/minstd_rand recovered via GCD + modular inverse, or MT19937 cloned by untempering 624 consecutive outputs.
- A verifier looks lazy about PKCS#1 v1.5 structure (e=3 keys, skips to the NULL separator without checking FF padding): Bleichenbacher signature forgery.

## Principles

- Implementations break, not algorithms. The exploit never defeats the hard math; it finds an implementation tell (reused nonce, unvalidated padding byte, leaked internal state, non-constant-time compare). Hunt the tell, not the cipher.
- Randomness is the load-bearing weakness. 'Random numbers are oxygen.' Bad entropy is the single most recurrent root cause, resurfacing as RSA shared primes (0.3-0.5% of internet keys) and the ECDSA nonce reuse that killed the PS3. Every public-key break in the book is an RNG break in disguise.
- Recoverable internal state defeats any PRNG: capture enough output (624 MT19937 words, two LCG outputs) and you reconstruct state and predict all future values. A CSPRNG can even be backdoored by design (DUAL_EC_DRBG, Q = e*P, crackable from ~2 bytes of output).
- Error messages, padding bytes, and response timing are an oracle. A single true/false 'valid padding?' bit decrypts an entire CBC ciphertext. Fix is 'say decryption failed, not invalid padding' plus constant-time everything.
- Construction order matters more than the primitive: secret-prefix MAC falls to length-extension, secret-suffix to collision, EtM risks length-extension, MtE risks padding oracles. Don't hand-combine cipher+MAC; use AEAD (AES-GCM/CCM).
- Time and control flow leak secrets. Non-constant-time memcmp short-circuits, square-and-multiply gives a power-trace side channel, branching on secret values leaks even through speculative execution. Fixes: crypto/subtle ConstantTimeCompare, Montgomery ladder, CMOV.

## Moves

- Batch-GCD shared-prime attack: pool many RSA public moduli, run pairwise/batch GCD, any GCD > 1 factors both keys instantly. Book demo: 512-prime chilled-RNG pool, 48 RSA-1024 keys, 14 recovered. This is the move for harvested-at-scale device/IoT key corpora.
- ECDSA reused-nonce recovery: scan a signature corpus for two sigs sharing r. Then k = (h1 - h2)/(s1 - s2) mod n, and d = (k*s - h)/r mod n. Total private-key recovery from public signatures alone (the fail0verflow PS3 break, Dec 2010).
- CBC padding-oracle decrypt: flip bytes in the prior ciphertext block, watch the valid/invalid-padding response, recover plaintext one byte at a time. BEAST variant: predictable/reused IV lets you slide the secret to a block boundary so each byte costs 2^8 not 2^128 guesses.
- Hash length-extension forgery: given a hash(secret||msg) MAC and the message length, set the hash's internal state to the known digest, append your data, produce a valid tag without the key. Real cases: Flickr, AWS v1, RADIUS 2024.
- PRNG cloning: recover minstd_rand (multiplier 48271, modulus 2^31-1) via GCD + modular inverse over math/big; or untemper 624 consecutive MT19937 outputs to reconstruct the full 19937-bit state and predict all future tokens.
- Wiener short-exponent attack: when d < (1/3)N^(1/4), expand e/N as a continued fraction and test each convergent denominator as a candidate private exponent. Pairs with Bleichenbacher e=3 forgery (prefix cube root by bisection + Valsorda suffix bit-flip cube root, stitched in the unvalidated padding region).
- Constant-time conversion as a defensive deliverable: replace memcmp with crypto/subtle ConstantTimeCompare (XOR-accumulate, OR not ADD), square-and-multiply with the Montgomery ladder, secret-dependent branches with CMOV; mlock + explicit_bzero secrets.

## Watch out

- Single-language, single-domain: the whole codebase is Go and it teaches BREAKING implementations, not designing protocols or formal proofs. It is the lab companion to a theory text (Katz-Lindell, Boneh-Shoup), not a replacement. Do not cite it for protocol design.
- It demonstrates attacks against deliberately vulnerable impl_ packages. Real targets are rarely so clean: production code may have partial mitigations (random IV, length checks, AEAD) that defeat the textbook version. Verify the precondition before claiming the break (e.g., confirm r is actually reused, confirm padding error is actually distinguishable).
- Several attacks have strict precondition gates that are easy to overstate: Wiener needs d < (1/3)N^(1/4); Bleichenbacher e=3 needs a verifier that skips FF-padding validation; batch-GCD only works when keys actually share a prime. A null result here is a logged result, not proof the crypto is sound.
- Restraint ethic applies: collecting a key corpus and finding a shared prime PROVES exploitability; you do not need to decrypt traffic or forge live signatures to land the finding. Names and the GCD hit are the finding. Sample minimally.
- Some specifics are point-in-time (Heartbleed CVE-2014, DUAL_EC SP 800-90A 2006-2015, RADIUS 2024). Treat version/CVE references as scoping anchors, re-verify the live target's version rather than assuming the book's exact build.
