# 40. Agentic AI For Dummies

**ISBN** 9781394379606  |  **Lobe** ai-agentic

> The non-technical map of the agentic-AI threat surface and governance vocabulary - reach for it to name the components, protocols, autonomy postures, and failure modes of agent systems you are attacking or defending.

## Reach for this when

- You need the shared vocabulary fast - tasks-vs-jobs, bounded autonomy, HITL/HOTL/adaptive autonomy, narrow-vs-emergent intent, simulated-not-conscious - to frame a finding or a disclosure so a non-technical exec/CISO understands the risk of an agent system.
- You are scoping the attack surface of an agentic deployment and need the component checklist: task decomposition, memory (short/long, episodic/semantic/shared), planning, tool use, goal-setting, plus the protocol plumbing (MCP, ANP, A2A, ACP).
- You want to map an agent's autonomy boundary - what constrains it (training, built-in safety, available tools, human-set goals, oversight) - to find where bounded autonomy is mis-set or the rollback/HITL gate is absent.
- You are building a governance or compliance frame for an assessment report and need the standards spine: NIST AI RMF (Govern/Map/Measure/Manage), ISO/IEC 42001 and 23894, EU AI Act, OWASP agentic, TRiSM.
- You need to inventory the alignment/value-misfire failure class for a threat model: reward hacking, Goodhart's Law, goal misgeneralization, automation bias, deskilling, hallucination, value-learning drift - and pair it with corrigibility (Bostrom/Russell) as the mitigation.
- You are running a tabletop on agent autonomy gone wrong and want the canonical real-world cautionary tale (the Replit agent that deleted a production database without permission) plus the four-phase pilot framework with logging of decisions+reasoning+confidence and a rollback mechanism.

## Principles

- GenAI is all talk, Agentic AI is all action - the qualitative leap that matters for attackers is that the system plans, decides, calls external tools/APIs, and pursues multi-step goals over time, so the attack surface is the tool-use and goal-setting layer, not just the text channel.
- Agency is bounded, not unbounded - autonomy is constrained by training, built-in safety, available tools, human-set goals, and oversight; the foothold is wherever one of those five constraints is mis-set, missing, or bypassable.
- Emergent does not mean uncontrollable, but it does mean non-deterministic and drift-prone - so verification is the load-bearing stage, not a formality; goal misgeneralization and value-learning drift are the slow failures you probe for.
- Simulated intent, not consciousness - goal-seeking that feels purposeful is borrowed from designers (narrow intent) or emerges beyond programming (emergent intent); accountability lives with the humans and the autonomy charter, never the agent.
- The unit of automation is the task, not the job - humans become orchestrators of agent swarms, which means privilege and trust now flow through the orchestrator-to-subagent boundary, a new lateral-movement and confused-deputy surface.
- AI mimics only analytical intelligence; the human it-factor (creative, intuitive, moral, emotional judgment) is the irreplaceable edge and also the thing automation-bias erodes - deskilling is a security risk, not just an HR one.

## Moves

- Decompose a target agent system into the building-block checklist (task decomposition / memory / planning / tool use / goal-setting) and the three-tier ladder (GenAI Chatbot / Near Agentic / Robust Agentic) across goal handling, memory, tool use, proactivity, adaptability, oversight, risk - then attack the weakest rung.
- Fingerprint the agent-communication plumbing by protocol: MCP (USB-C for AI, Anthropic, JSON-RPC client-server) -> chain to book #38 Agentic Coding with Claude Code and #41 Learn Mistral AI for live MCP tooling; ANP (decentralized, DIDs, JSON-LD); A2A (Google, Slack-channel-for-agents); ACP (IBM BeeAI, RESTful/HTTPS). Each protocol is a distinct exposed-surface fingerprint for the aimap/tome corpus.
- Map the autonomy posture (HITL vs HOTL vs adaptive autonomy) and confirm a rollback mechanism plus logging of decisions+reasoning+confidence exists; absence of either is a finding (surface open, oversight not exercised).
- Run the alignment-failure taxonomy as a threat-model checklist against any agent: reward hacking, Goodhart, goal misgeneralization, automation bias, hallucination, redlining/bias - and probe prompt-injection defense (red-team with the gandalf.lakera.ai pattern, output filters, guardrails).
- Use context engineering vs prompt engineering as a recon split - context engineering = onboarding an employee (persistent memory, tools, system components, RAG); the persistent-memory and RAG store (Pinecone, FAISS, vector embeddings) is the data-at-rest target where PII/PHI accumulates.
- Translate any finding into the governance spine for the report (NIST AI RMF, ISO/IEC 42001, EU AI Act, OWASP agentic, TRiSM) so the remediation is fixable in the real world and the CISO feels the risk.

## Watch out

- This is a Dummies primer - code and architecture are described conceptually, never implemented. Do not cite it as a technical reference or expect a working primitive; supplement with #39, #38, #41 and the framework labs for anything you have to build or exploit.
- Its posture is pragmatic optimism / pro-adoption. The governance is framed as governable-and-standards-backed, which understates how often the rollback mechanism, HITL gate, and logging are absent in the wild. Treat the controls as the to-verify list, not the as-built reality.
- The numbers are vendor/marketing-flavored and dated to early 2025: 115-180M daily users, McKinsey $2.6-4.4T, Goldman ~7% GDP, Anthropic 90.2% multi-agent uplift, Lightcast one-third-of-skills-changed. Cite as directional framing, never as a verified finding - primary-source the claim before it lands in a report.
- Eight-intelligences framing (Gardner-derived) and the it-factor are rhetorical, not a security taxonomy. Useful for exec narrative, useless as an analytic control.
- Standards name-dropping (NIST AI RMF, ISO/IEC 42001/23894, EU AI Act, OWASP agentic, TRiSM, Constitutional AI, mechanistic interpretability, formal verification) is broad and shallow. Use the names to anchor a report section, then go to the actual standard text; the book does not give you implementation depth on any of them.
- Emergent-does-not-mean-uncontrollable is the author's reassurance, not a guarantee. For an attacker it is the opposite: emergent and drift-prone is exactly the unverified behavior to exploit. Read its optimism as the defender's blind spot.
