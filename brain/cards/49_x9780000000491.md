# 49. Reverse Engineering for Beginners

**ISBN** x9780000000491  |  **Lobe** offensive

> Yurichev's free from-zero RE manual that builds the compiler-output-to-assembly mental model across x86/x64/ARM/MIPS/Java, then weaponizes it for the parts we actually need: compiler/toolchain fingerprinting, magic-number and constant recognition, backdoor-string hunting, and entropy-based blob triage, the byte-level discipline that turns an opaque binary or a compiled agent runtime into attribution.

## Reach for this when

- A scanner or aimap deep-enumerator pulls back an opaque binary, a firmware blob, or a stripped agent-platform helper and we need to identify what compiled it, which language, and which open-source libraries it links before naming a finding (Chapter 5: MSVC/GCC/Intel-Fortran/Watcom/Borland DLL-import and name-mangling tables, CryptoPP/zlib string spotting)
- We harvest an encrypted-looking config value, an XML <Data> blob, or a vector-DB record field and have to decide is-it-base64 / is-it-compressed / is-it-encrypted from the metadata alone, without exfiltrating, using Shannon-entropy variance and block-size analysis (Chapter 8.7 + Appendix 9.2 entropy method)
- We find a weird non-RFC URL path, magic string, or hardcoded constant in firmware or a binary and need to judge whether it is a backdoor or a benign artifact (Chapter 5.4.4 TP-Link userRpmNatDebugRpm backdoor, magic-date constants like Stuxnet 19790509, MD5 init constants 0x67452301)
- An aimap/scanner crash or 0x41414141 in a register needs triage to tell a corruptible parser from noise, and we want the buffer-overflow / stack-canary mental model before claiming exploitability (Chapter 1.20 buffer overflow + protection methods)
- We are reversing a copy-protection, license, or auth-check routine in a proprietary AI-infra appliance and want the patching and trial-extension playbook (Chapter 5.3 extending trial period / removing nag dialog, Chapter 8.5 dongle emulation, 8.10 SAP password-checking functions)
- We need to read what a managed-code agent or Java/JVM helper actually does at the bytecode level when source is absent (Chapter 4 Java bytecode reversing, simple patching)

## Principles

- Compile-look-repeat is the whole method: write small C, read the compiler's assembly, do it enough times that the C-to-asm mapping is imprinted, so any disassembly back-projects to recognizable source structure (the inverse of writing code is the core RE skill)
- Strings, constants, and magic numbers are the cheapest authoritative source in an unknown binary: run strings first, then googleable assert() conditions and file names recover variable/struct names and identify open-source libraries, and recognizable constants (MD5 init, CRC polynomials, MZ/MThd headers) fingerprint algorithms instantly
- Entropy is a metadata-only probe: high entropy with low variance and even block-aligned sizes says compressed-or-encrypted; a missing compressor header plus block-size divisibility distinguishes encryption from compression, all without decrypting anything
- The same patterns recur across every ISA: function prologue/epilogue, the stack growing backwards, calling conventions (cdecl/stdcall/fastcall/thiscall/SysV), two's complement, big-vs-little-endian; learn the pattern once and read x86, ARM, MIPS, and JVM bytecode as dialects
- Non-RFC, non-googleable, non-algorithmic byte sequences are inherently suspicious: a string that fits no protocol, library, or error-message convention is a backdoor tell, and security-through-obscurity (base64-wrapped) just delays the visual scan, it does not defeat it
