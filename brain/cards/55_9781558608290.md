# 55. Bioinformatics: Managing Scientific Data

**ISBN** 9781558608290  |  **Lobe** bio-compute

> A 2003 edited survey (Lacroix and Critchlow) of eight production bioinformatics data-integration systems, SRS, Kleisli, TAMBIS, K2, P/FDM, GeneExpress, DiscoveryLink, and KIND, that frames the core problem as semantic heterogeneity across autonomous, format-drifting biological sources and maps the warehouse-vs-federation-vs-mediator design space, wrapper architectures, cost-based query optimization, and ontology-driven glue knowledge for turning scientists' questions into executable queries.

## Reach for this when

- Deciding between a materialized data warehouse, a federated/distributed database, and a wrapper-based mediator when integrating many autonomous sources, and needing the concrete tradeoff table (materialized vs non-materialized, scalability vs semantic consistency).
- Designing a wrapper layer that exposes heterogeneous sources (flat files, relational DBs, Web sites, BLAST, XML) under one query interface and must compensate for SQL functions a source lacks.
- Reconciling conflicting or overlapping records across sources where there may be no single right answer: concept identification, concept overloading, entity resolution, controlled-vocabulary mapping.
- Building or evaluating a query optimizer that must cost operations pushed down to sources with wildly different capabilities and unknown cardinalities (a BLAST call is seconds or hours depending on inputs).
- Standing up ontology and semantic-integration glue (TAMBIS TaO, GO, UMLS, SNOMED, KIND domain/process maps) to link sources that share no join key.
- Hardening an integration against sources whose schemas and interfaces change roughly every six months without silently breaking downstream consumers.
- Choosing evaluation criteria and cost/benchmark methodology for a data-management system (the six-metric x two-perspective rubric of Chapter 13) on a buy-or-build decision.
- Tracking data provenance, quality, ownership, and HIPAA/privacy exposure when fusing clinical and genomic data.

## Principles

- The N-squared problem: connecting N sources point to point needs N(N-1)/2 programs; a Wiederhold-style mediator with a shared model plus one wrapper per source collapses that to N, which is why the mediator/wrapper pattern dominates the book.
- Three architectures on one axis: warehouse (materialized, secure behind a firewall, faster, e.g. GeneExpress GXDW with 5GB+ of gene annotations refreshed quarterly), federation, and mediator (wrappers translate raw source data into a common model, usually XML). Barbara Eckman's six dimensions (browsing/querying, declarative/procedural, generic/hard-coded, semantic/syntactic heterogeneity, warehouse/federation, relational/non-relational) classify any solution.
- Syntax is easy, semantics is hard: concept identification (do two records name the same gene), concept overloading (both say 'gene' but one means postulated and one means known-coding), non-invertible transformations, and reconciliation where two sources legitimately disagree on the same sequence so there is no right answer.
- The relational model (Codd 1970) buys declarative SQL, relational algebra (projection, selection, join, union, difference), Selinger-style cost-based optimization (1979), views for logical data independence, and multi-user concurrency, at the price of forcing semi-structured biology into flat relations.
- Kleisli's complex-object model (sets, bags, lists, records, variants) with the CPL and sSQL languages, grounded in Nested Relational Calculus and monad/structural-recursion theory, gives a self-describing exchange format and optimizations (vertical loop fusion, migrating projection/selection/join to the RDBMS); it handles 60+ source types.
- Wrappers are the extensibility unit: a DiscoveryLink wrapper (C++ shared library, ISO SQL/MED) can be prototyped in days; the federated server compensates for missing SQL and, uniquely (Garlic lineage), takes query-specific plans and cost/cardinality estimates back from wrappers during optimization.
- Ontology-driven integration: TAMBIS TaO (~1800 concepts in GRAIL description logic, with subsumption and sanctioning) drives query formulation, while KIND's model-based mediation lifts sources to conceptual models plus domain maps and process maps (F-logic, FaCT reasoner) to link sources across 'multiple worlds' that share no join key.
- Evaluation is context-bound: six metrics (efficiency, extensibility, functionality, scalability, understandability, usability) across implementation and user perspectives; scalability and semantic consistency are mutually exclusive goals; text retrieval is scored by precision and recall.

## Moves

- SRS: index flat-file databanks with the Icarus meta-data language (EBNF grammar, token server with lazy parsing), build hub tables and bi-directional indexed links queried with the < and > operators for navigational cross-references; queries typically complete in under a minute via pre-computed indices.
- Kleisli/CPL: express cross-source joins and transformations in CPL or sSQL over the complex-object model, run on Standard ML of New Jersey, use the self-describing exchange format and the Pizzkell drivers (CPL2Perl, CPL2Java); let the optimizer apply loop fusion and push projections/selections/joins down into the RDBMS.
- DiscoveryLink registration flow: CREATE WRAPPER then CREATE SERVER then CREATE NICKNAME then CREATE FUNCTION MAPPING then user mapping; model BLAST as a virtual table indexed on query_seq, model a Web source's Boolean search as function contains(A,B,C); tune push-down with SAT parameters PUSHDOWN, BASIC_PRED, MAX_TABS, CPU_RATIO.
- Federated query optimization: dynamic-programming join enumeration (single-table, then two-way, then n-way), bindjoin vs hash-join vs nested-loop plans, wrappers return wrapper plans with cost and result-size estimates (worked example weighs a 503.2s plan against a 28s plan), with query rewrite before cost-based optimization.
- TAMBIS: pose a query over the TaO ontology, GRAIL builds a subsumption lattice and sanctions only biologically-meaningful concept combinations, then the Sources and Services Model plus an augmentation heuristic map the conceptual query to a QIF plan executed through BioKleisli/CPL (now Java) wrappers.
- K2: view integration over ODMG (ODL + OQL), the K2MDL mediator definition language, composable mediators, IDD/DDD drivers, and the W4F wrapper factory over Java/RMI/JDBC.
- P/FDM: query a functional data model in Daplex under the ANSI-SPARC three-schema/five-level architecture; a Prolog mediator parses to ICode, simplifies, rewrites, then a query splitter cuts the query into per-source chunks and a result fuser recombines.
- GeneExpress warehouse: three data spaces (sample, gene annotation, expression) in GXDW plus Gene Expression Array (GXA) 3D matrices per chip/measurement type; MAS 4.0/5.0 algorithms over Affymetrix GeneChip (PM/MM probe pairs, 25-bp oligos, up to ~20 pairs per probe set); SNOMED for samples, GO/UniGene/LocusLink for genes; GX Connect ETL, AADM exchange format; benchmarked to 300 concurrent users.
- KIND: register a source as CM(S) = OM(S) + ONT(S) + CON(S) (object model, local ontology, contextualization), contextualize local concepts as local-as-view axioms on the mediator ontology (UMLS, GO), compile domain maps to F-logic via a mapping Psi, and run FaCT for consistency and concept-hierarchy derivation.
- Analysis tools to integrate and their tradeoffs: BLAST (heuristic, fast) vs Smith-Waterman (dynamic programming, ~50x slower but more sensitive), plus FASTA, CLUSTAL W, HMMER, PROSITE/PFSCAN, over sources GenBank, Swiss-Prot, EMBL, Entrez, PubMed, OMIM, KEGG, Pfam, InterPro.

## Watch out

- Published 2003: the specific products are dated or gone (DiscoveryLink absorbed into IBM InfoSphere, discoveryHub was Kleisli's commercial arm, SRS/LION defunct) and every data-source size and version is two decades stale. Read it for design patterns, not as a product guide.
- It is an edited volume where each system chapter is written by that system's own authors, so superiority claims are self-reported; Chapter 13 explicitly refuses to rank the systems or run a head-to-head benchmark.
- It pre-dates NoSQL, JSON, cloud data lakes, and vector/RAG stores; the semi-structured vs relational debate it is still arguing has since settled toward the semi-structured side.
- Heavy on relational/SQL and description-logic formalism (F-logic, GRAIL, monads); the KIND chapter's F-logic compilation is theory-dense and light on running-system evidence.
- Worked examples assume biology fluency (dendritic spines, Purkinje cells, probe sets, microarray normalization); the integration principles generalize but the illustrations do not.
