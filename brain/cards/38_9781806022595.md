## Principles

- The harness, not the LLM call, is where engineering lives. The model invocation is straightforward; reliability comes from which context is sent at each step. Applies directly to the orchestrator+subagent pattern in CLAUDE.md.
- Context is dynamic and rots. Prompts are static; context grows with every tool call until poisoning/confusion/clash corrupts output. Every primitive maps to one of Write (persistent memory), Select (retrieval), Compress (/clear,/compact), Isolate (subagents).
- Subagents are the isolation primitive: own context window, receive only the single constructed prompt, return one condensed response - heavy work never bloats the main thread. The description field controls BOTH when a subagent fires AND how it is prompted.
- A deep agent = planning tool (TodoWrite/TodoRead) + subagents + filesystem-as-context-engine + large system prompt. Shallow ReAct agents lack these and collapse as iterative tool-calling accumulates context. This is the structural reason the  chain can run long.
- Least privilege is a security control, not hygiene. Over-provisioning is tool pollution: more tokens AND wider attack surface. An untrusted skill or malicious subagent description is a real injection vector because the description is appended to the main agent's system prompt.
- The Goldilocks zone: give a reasoning framework, not a flowchart. Over-specific prompts treat the LLM as a deterministic state machine; over-vague gives no signal. Heuristics like 'choose the simplest solution' (greedy) beat hardcoded step counts.

## Moves

- Cut MCP context bloat: measure with /context, then scope with a per-task .mcp.json and run claude --mcp-config <file> --strict-mcp-config to ignore the default hierarchy entirely. Worked example drove MCP from ~20% to ~2.4% of the window. Apply before a long parallel scan-harvest phase where every wasted token compounds across lanes.
- Shape a subagent two ways: edit the description to control invocation + the prompt the orchestrator constructs ('simplify to the GIST'), and edit the body to control output formatting. Demonstrated end-to-end on the Mermaid subagent.
- Wire a UserPromptSubmit hook (context-switcher.sh) that idempotently appends @-imports to CLAUDE.md by git branch or query keyword, using grep -qxF to avoid duplicate imports - the mechanism behind per-lane wardrobe/outfit loading.
- Harden a custom slash command with allowed-tools front matter (Bash(git add:*), git status, git commit) and shell-inject live state via !`git status` / !`git diff HEAD` - framed explicitly as RAG + least privilege. Direct template for arsenal skills that need scan/banner state as context.
- Use plan mode (Shift+Tab / /plan, read-only) with Opus to generate and refine a SPEC/CLAUDE.md, tag it with @, then implement against it with Sonnet - the spec-driven discipline that mirrors the orchestrator-writes-the-task-spec-first rule.
- Run a skill in isolation with fork + agent: Explore front matter, and set disable-model-invocation: true to force slash-only invocation when you do not want the model auto-firing a heavy lane.
- Apply the parallelization decision rule: start sequential, parallelize only after confirming tasks do not interact. Tightly-coupled features, shared-state/ordering (configs, migrations, shared types), small tasks (session overhead exceeds savings), and exploratory work all argue for sequential.
- Manage the filesystem as a context engine: keep the selected set (red) minimal while fully covering required-information (green) from available-context (blue); avoid under-retrieval, over-retrieval, misaligned retrieval, and window overflow.

## Watch out

- Severely version-sensitive: Claude Code v2.1/2.2, Sonnet 4.5, Oct-2025 feature dates, plugins published Oct 9 2025. UI flows, slash commands, and token numbers will date fast - treat specific commands as illustrative, the four strategies and deep-agent definition as durable.
- It is a Claude Code book, single-tool. The author cross-sells his own MCP titles; for vendor-neutral pattern coverage go to #39, not here. Do not over-generalize Claude-specific primitive names to other harnesses without checking.
- Author is a Google Cloud employee writing a personal book about an Anthropic product, with explicit non-affiliation notices - opinionated and promotional in places (Infinite Agentic Loop, IndieDevDan tooling). Take the enthusiasm as advocacy, not benchmark.
- The token-cost figures (58 tools = ~55,000 tokens; 20%->2.4%) are single worked examples, not measured distributions. Useful as order-of-magnitude intuition, not as guarantees - verify with /context on your actual loadout.
- Light editing slips noted in the text (duplicated chapter title, OCR typos like 'pec-driven', 'feistel/fiestal'); some Desktop-chapter screenshots are explicitly not reproducible step-by-step. Not a precision reference for exact UI sequences.
- Rewind/checkpoint does NOT track Bash commands or manual edits and only retains for up to 30 days - do not rely on it as a safety net for irreversible actions; the CLAUDE.md confirm-before-irreversible gate still governs.
