# 54. Hacking: The Art of Exploitation, 2nd Edition

**ISBN** x9780000000545  |  **Lobe** offensive

> Erickson's from-the-registers-up exploitation primer: C and x86 assembly through the hacker's eye, then buffer/heap/format-string corruption, raw-socket networking and TCP hijacking, hand-written shellcode, mitigation bypass, and crypto attacks, all anchored to the Hacker Ethic that understanding the byte layer is the prerequisite for finding unintended uses of any system.

## Reach for this when

- We are reading a crash, a hexdump, or a memory layout below the language level and need the EIP/ESP/stack/heap mental model to know what 0x41414141 in a register actually means before calling a finding exploitable
- We are writing or decoding a custom probe/shellcode payload for an AI-infra service: hand-rolling raw sockets, libpcap-style packet decode, port-binding vs connect-back behavior, null-byte-free buffers, or socket-reuse to avoid opening a flagged outbound connection
- A target service is a memory-unsafe C parser (model server, vector-DB native backend, embedded/IoT daemon) and we need to reason from stack-overflow to function-pointer/GOT overwrite to control flow rather than fuzzing blind
- We need the first-principles substrate under our heavier offensive cards: how two's complement, network byte order, format specifiers, and pointer arithmetic actually behave on the wire and in memory
- We are evaluating crypto we found on the wire (WEP/RC4 keystream reuse via the FMS attack, RSA key sizing, crypt()/salted-hash password storage, the password probability matrix for brute-force ordering, MITM-on-SSH host-key swap) and need the attack mechanics, not just the names
- We are calibrating IDS/log footprint during an authorized engagement: egress filtering, the port-31337 red flag, log-overwrite, and the shroud proactive-defense lens on what traces our actions leave

## Principles

- Hacking is creative, rule-following problem-solving: finding unintended or overlooked uses of a system's own laws, which makes deep understanding of the substrate the actual weapon, not any single exploit
- Exploitation generalizes to three steps every time: memory corruption, then a change in control flow, then execution of attacker code; every countermeasure (NX stack, ASLR, canaries) targets one of those steps and every bypass (ret2libc, info-leak, function-pointer corruption) routes around it
- You do not understand a primitive until you can build it from registers up: the book teaches C and x86 assembly first precisely because reading the binary/memory layer is the prerequisite for everything above it
- Logic corruption is as valuable as code execution: overwriting a logfd, a function pointer, the GOT, or an is_admin-equivalent flag defeats the application's own intent without ever running shellcode
- Cryptosystems fail at implementation and key-scheduling, not only at the math: WEP's RC4 keystream reuse via weak IVs (FMS), 40-bit export keys, and salted-but-weak password hashes are the recurring real breaks, and strong crypto doubles as IDS evasion
