# 44. Attacking Network Protocols

**ISBN** 9781492067504  |  **Lobe** offensive

> Forshaw's field manual for reducing any unknown wire protocol to content/encoding/transport, then capturing, reversing, reimplementing, fuzzing, and exploiting it - the book you reach for when the signal lives BELOW the HTTP status layer.

## Reach for this when

- A target speaks a non-HTTP or proprietary protocol and you need to read it from the wire up - gRPC vector-DB backends, Milvus 9091, raw banner services, ICS/OT field-bus traffic, IoT device protocols where the HTTP status code tells you nothing
- You have a black-box networked device or app and no docs/source - the capture -> structure -> reverse -> reimplement -> root-cause -> exploit loop is the whole job
- You need to MITM a client that does TLS pinning-lite or a custom transport and want the mechanics: self-signed CA into the trust store, ServerCertificateSubject CN trick, proxy taxonomy by client cooperation
- You captured a binary blob and need to decode it - TLV, varints, endianness, the four variable-length-data conventions - before you can fingerprint or fuzz it
- You want to weaponize a memory-corruption or logic crash in a memory-unsafe parser and need the triage -> shellcode -> mitigation-bypass pipeline
- You need to build a custom protocol probe/fuzzer for an AI-infra service that aimap does not yet fingerprint and want the grammar-driven generation ladder

## Principles

- Three-layer decomposition (Content / Encoding / Transport) before any analysis - attack the right layer instead of conflating them; this is the analytical spine
- Capture has a deliberate passive/active tradeoff: passive (Wireshark, tcpdump, strace/DTrace/ProcMon syscall tracing) observes without disturbing but is blind to encryption; active (proxies, MITM) modifies and replays but is intrusive and detectable
- The proxy is chosen by how much the client cooperates: port-forward (one endpoint) -> SOCKS 4/4a/5 (client-cooperative) -> HTTP forward -> reverse HTTP; when the client cannot be reconfigured, pull traffic with DHCP spoof / ARP poison + iptables SNAT/DNAT
- Reverse engineering the binary is the authoritative source when docs are absent - and managed code (.NET CIL via ILSpy, Java via JD) is nearly source-equivalent because of rich metadata; native x86/x64 in IDA is the harder path
- Reimplementation proves understanding: replay captures, repurpose the app's own parsing via reflection/ctypes, or rebuild the client - you do not understand a protocol until you can speak it
- Fuzzing scales by sophistication, not magic: dumb (/dev/urandom into nc) -> mutation (bit-flip + checksum repair) -> grammar-driven generation, each trading effort for coverage and the ability to pass validation gates

## Moves

- Decompose a captured protocol into content/encoding/transport, then read the binary vocabulary: signed/unsigned/varint integers (two's complement, 7-bit), IEEE 754 floats, network-order big-endian, TLV, and the four variable-length conventions (terminated / length-prefixed / implicit / padded)
- Run passive capture two ways at once: Wireshark/tshark on the wire AND syscall tracing (strace Linux / DTrace macOS-BSD / Process Monitor Windows) to see how the app reads/writes the socket even under encryption
- Stand up a MITM proxy with Canape Core .csx scripts (FixedProxyTemplate), extend Wireshark with a Lua dissector, and parse structures in Python struct
- Defeat TLS by minting a root CA (generate_ca_cert.csx), importing it into the OS trust store, and setting tls.Config.ServerCertificateSubject to CN=127.0.0.1 to clear RemoteCertificateNameMismatch
- Redirect a victim on the LAN: DHCP spoof (hand them your gateway/DNS) or ARP poison with Ettercap, then iptables SNAT/DNAT through your listener
- Triage a crash in GDB/CDB/LLDB: read fault type (SIGSEGV vs Access Violation), spot 0x41414141 ('AAAA') in EIP/EAX/stack to confirm return-address or VTable overwrite, harden with AddressSanitizer (-fsanitize=address) and Windows Page Heap (gflags +hpa)
- Climb the fuzzing ladder: cat /dev/urandom | nc host port -> single-bit mutation with checksum/length recalculation -> grammar generation; pair AFL for coverage-guided runs
- Write x64 shellcode in NASM per the Linux ABI (RAX=syscall number, RDI/RSI/RDX/R10/R8/R9 args; execve=59, write=1, exit=60), solve position-independence with RIP-relative lea [rel label], or generate with msfvenom -p linux/x64/shell_reverse_tcp LHOST/LPORT + nc -l listener
- Exploit logic not just memory: flip an is_admin int from 0 to 1 in a {socket; is_admin} session struct to unlock a privileged CMD_RUN_COMMAND path - corruption to defeat application logic
- Bypass mitigations: Ret2Libc/ROP gadgets and stack pivots (xchg esp,eax; ret) for DEP, info-leaks and partial low-byte overwrites for ASLR, local-function-pointer corruption used-before-canary-check for stack canaries

## Watch out

- Tooling is Forshaw-centric and dated: Canape Core (.NET Core, .csx scripts) is his own framework and not a community standard - the techniques transfer but expect to re-implement in mitmproxy/Scapy/raw Python rather than copy his C# verbatim
- 32-bit-era exploitation framing in places (EIP, classic stack overflows, x86 ROP) - modern targets are x64 with EIP->RIP, full ASLR/PIE, CFI/CET, and stack canaries everywhere; treat the mitigation-bypass chapter as foundational mental model, not a present-day exploit recipe
- Deliberately under-covers HTTP/web app surface - this is by design (he points to Web Application Hacker's Handbook), so do not reach here for HTTP-specific attacks; pair with web-app references
- Chapters 6 and 10 assume comfort with x86/x64 registers and disassembly - it is not a from-zero assembly primer; weak RE fundamentals will stall you
- The 'fuzz anything' enthusiasm carries a real-world stop: never run the /dev/urandom-into-nc fuzzer (or any active capture/redirection) against ICS/OT, medical, or production targets - Forshaw says it as a joke but it is the exact NuClide restraint ethic; active MITM is intrusive and detectable by design
- ARP poison / DHCP spoof / iptables SNAT-DNAT are loud, stateful LAN attacks - they are capture primitives, not stealth; in an authorized engagement they trip IDS and can disrupt other hosts, so scope them tightly
