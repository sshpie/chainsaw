# 48. Pentesting APIs and Cloud Applications

**ISBN** x9780000000484  |  **Lobe** offensive

> A compact WAPTXv2 field module that treats the API as a transport you tamper with end to end - WSDL/WADL/Swagger recon, token x endpoint access-control matrix testing, CORS credentialed-origin theft, and the cloud chain that ends at Lambda env-var AWS key exfil via serverless event injection - the book you reach for when the attack surface IS the API and the storage bucket behind it.

## Reach for this when

- Fingerprinting an exposed agent or AI-infra service that speaks REST/SOAP/GraphQL and we need to pull its self-describing contract first - ?wsdl/?wadl, /swagger, /graphql introspection - to enumerate every method before probing, the same move as reading a vector-DB schema before touching records
- Running the access-control matrix on a multi-tenant AI platform (LibreChat/Langfuse/RAGFlow per-tenant): generate a token per role, cross every endpoint with every token plus the no-token case, to find the authorization-bypass and the no-auth-on-default read
- We have a GraphQL endpoint (one /graphql, Query + Mutation) and need the introspection-then-mutation recipe to read sensitive fields or hit a deleteUser mutation that has no built-in authz
- A Shodan/Censys harvest surfaced S3 buckets or cloud assets and we need the s3recon + aws-cli verification ladder (public list -> read object -> write/ACL) and the signed-URL/signed-cookie temporary-access trap
- Assessing a serverless/FaaS target where a user-controlled value reaches os.system - serverless event injection to RCE, then env or cat /proc/self/environ to lift the Lambda AWS keys, the cloud-native privesc primitive
- Triaging a CORS finding on an API: distinguishing harmless reflected ACAO from the actionable Access-Control-Allow-Origin reflection plus Access-Control-Allow-Credentials:true that lets an attacker-origin script read authenticated responses, including the null-origin case

## Principles

- The API is just another transport for backend data, so tamper with everything it carries - param injection (SQLi via SOAP body), XXE/SSRF through DTD, stored XSS smuggled in CDATA - the predefined-method facade does not make the parameters safe
- Recon is contract-first: get the self-describing doc (WSDL/WADL/Swagger/GraphQL introspection), then ask whether local and public docs match, because hidden methods (Rundeck adhoc OS-command run) are exactly the insecure ones stripped from public docs but live on the box
- Access control is tested as a full matrix, not spot-checked: a working request to every endpoint x a token for every user role x the no-token baseline; API tokens inherit all the session-cookie sins (low entropy, no invalidation, leakage, pre-generation)
- CORS severity is the AND of two headers: a reflected/wildcard Access-Control-Allow-Origin is only a credentialed-theft primitive when paired with Access-Control-Allow-Credentials:true; without it a static page leaks nothing
- Serverless rewrites the exploit economics - functions live minutes with no local state, so backdooring is pointless; the prize is the ephemeral RCE used to read environment variables, because Lambda stores the AWS keys there and those keys carry the function's full IAM privilege
