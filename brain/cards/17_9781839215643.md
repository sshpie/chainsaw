# 17. SQL Injection Strategies

**ISBN** 9781839215643  |  **Lobe** offensive

> The canonical SQLi taxonomy plus matching defense matrix as a reach-for vocabulary card: every injection primitive (UNION, error-based, Boolean/time blind, splitting-balancing, NoSQL $ne) tagged with its DBMS-specific payload, framed as the trust-the-input failure class that generalizes from SQL to SOAP/IoT/LLM tool-input.

## Reach for this when

- A target concatenates user input into a query string of any kind (SQL, NoSQL, SOAP, IoT status field, or LLM tool argument) and I need the full primitive catalog ranked by DBMS so I pick the right payload before fingerprinting the engine.

- The app does not echo query output and I am stuck on a blind channel: I need the Boolean binary-search-over-ASCII, time-based delay (SLEEP/BENCHMARK/WAITFOR/DBMS_LOCK.SLEEP), and error-channel (ExtractValue XPATH leak) techniques side by side.

- I need to explain injection lineage and shared-vocabulary SQLi taxonomy to a non-specialist stakeholder or CISO and want a clean teaching scaffold with real-dollar cases (1.2B credentials, Starbucks accounting DB).
- I want a safe lab-build template (OWASP BWA + Kali + sqlmap + ZAP, Host-Only network) to validate an injection primitive without touching a live target.

## Principles

- SQL injection is an application-layer bug, not a database flaw: the DB faithfully executes any syntactically valid string handed to it, so the failure is always the application concatenating untrusted input. This is the same root cause as LLM prompt-injection and tool-input-injection: trust-the-input.
- Defense must be simultaneous and layered, never singular: any one control (client-side JS checks, single-quote filtering, even parameterized queries that wrap a vulnerable stored procedure) is bypassable, so only stacked code-level plus platform-level defenses approach safety.
- Attack-before-defense is the load-bearing pedagogy: know-your-enemy first means every countermeasure is motivated by a concrete bypass you already executed. This mirrors NuClide verify-the-finding discipline (scan produces candidates, verification produces findings).
- Blind is the realistic default, not the exception: most production apps do not echo output, so Boolean inference, time delays, and error-channel extraction are the working techniques and binary search over ASCII makes character-by-character recovery tractable.
- Whitelisting beats blacklisting because blacklists fail open against novel encodings and new attacks while whitelists fail closed by rejecting anything not explicitly envisioned.
- A shared database multiplies blast radius: one MySQL instance behind many apps means injecting one app exposes every other app's schema. This is chain-thinking made concrete: least privilege and separation of duties are the chain-breakers.

## Moves

- Tautology auth bypass: ' OR 1=1 -- - (or x' OR '1=1'-- in the username field) makes WHERE always true; the comment sequence strips the trailing app-supplied quote.
- UNION column discovery: pad ' UNION SELECT 1,@@VERSION,3,4,5,6,7 -- - by trial-and-error to match the original column count, then read output from whichever columns render (often 2,3,4).
- Error-message DBMS fingerprint: submit a lone single quote to trigger a verbose SQL error that leaks engine, table names, and query structure before you commit to a payload family.
- Schema enumeration per engine: MySQL information_schema.tables/columns; MSSQL master..sysdatabases and sysobjects WHERE xtype='U' (U=table, P=proc, V=view, TR=trigger, X=ext proc); Oracle all_tables/all_tab_columns and the always-readable DUAL one-row table.
- Boolean binary-search blind: ' OR ASCII(SUBSTRING((SELECT NAME FROM SSN LIMIT 1 OFFSET 0),1,1)) >= 128 -- - then halve the 0-255 range each iteration (128->64->96->80->72->76->72 recovers 'H').
- Time-based blind by engine: MySQL SLEEP(15)/BENCHMARK(10000,...); MSSQL WAITFOR DELAY '0:0:15'; Oracle BEGIN DBMS_LOCK.SLEEP(15); END; or UTL_INADDR.get_host_name out-of-band trick. Combine with IF(SUBSTRING(...)='x',SLEEP(15),0) for inference over latency.
- Filter-evasion: CHAR(27) reconstructs a stripped single quote at runtime; splitting-and-balancing rewrites id=3 as id=2+1 and 'Jonathan' as 'Jo'||'nathan' to slip balanced equivalent subqueries past naive filters.
- Error-based exfil: ExtractValue('x', CONCAT('=',(SELECT ... LIMIT 1 OFFSET n))) leaks one row at a time inside an XPATH syntax error; INSERT-form exfil smuggles test','test',(SELECT password FROM mysql.user WHERE user='root') into a registration form not meant to return data.
- NoSQL injection: GET ...password[%24ne]= becomes {"password":{"$ne":""}} so MongoDB find() always succeeds; works as JSON body or urlencoded POST.
- Automate then verify: sqlmap -u URL -> --dbs -> --tables -D <db> -> --dump (with --data for POST, built-in hash cracking, output as CSV in ~/.sqlmap/output); OWASP ZAP Automated Scan = Spider + Scanner -> Alerts, plus the Fuzzer with custom SQLi wordlists.

## Watch out

- This is a beginner Packt primer, not advanced tradecraft: foundational vocabulary and a teaching scaffold, nothing novel for an ICS/OT specialist already publishing CVEs. Reach for it as a refresher and a stakeholder-explainer, not for depth.
- The lab is stale: OWASP BWA was discontinued in 2015 and the targets (Mutillidae II, SQLol, Peruggia, Vicnum) run ancient MySQL (5.1.41 on Ubuntu 12). Payloads and error behavior reflect that era; modern engines, prepared-statement defaults, and ORMs change the picture.
- Several APIs shown are deprecated: mysql_real_escape_string() is removed in modern PHP, and escaping is the weakest control in the stack anyway. Treat the book's escaping examples as historical; parameterized queries are the real fix.
- Cited stats are marketing-flavored and dated (39-second attack, 65.1% Akamai figure, 30,000 sites/day): fine for a CISO slide to make risk felt, but do not treat them as current ground truth or cite them as primary evidence.
- Escaping and blacklist validation are presented alongside the strong controls but are bypassable (CHAR() reconstructs stripped quotes, blacklists fail open); do not let the catalog's even-handed presentation imply these are acceptable standalone defenses. Whitelist and parameterize are the load-bearing ones.
- The book teaches against echoing-output and obviously-vulnerable PHP patterns; real engagements are blind-by-default, so over-indexing on the visible UNION examples under-prepares you. The blind/error-channel sections are the operationally important half.
