# 52. Practical Malware Analysis

**ISBN** x9780000000521  |  **Lobe** defensive

> Sikorski and Honig's analyst field manual that reduces an opaque binary to verified indicators through the four-quadrant method (basic/advanced x static/dynamic), then weaponizes that understanding into host and network signatures - the book you reach for when a sample's behavior, its imports, or its beacon must become a reproducible detection, not a guess.

## Reach for this when

- We pull an unknown binary, a dropped payload, or a packed agent artifact off a compromised AI-infra host and need the static-first ladder: hashes -> strings -> PE imports -> sandbox detonation before touching a disassembler.
- We have a sample's beacon or C2 traffic and must turn it into a durable network signature: User-Agent quirks, URI structure, dsize/flow Snort options, separating host-derived variable fields from static content that belongs in the rule.
- We are about to research an attacker domain/IP and need the OPSEC discipline (indirection, passive-DNS, whois/RobTex/DomainTools, embedded-canary-domain awareness) so our lookup does not tip the operator - the same restraint as our passiveV2 posture.
- An aimap fingerprint or recon read returns near-empty strings/imports and we need to recognize packing/obfuscation (LoadLibrary+GetProcAddress only, PEiD/UPX tells) before concluding a service is benign or dead.
- We need the import-table reading skill to infer capability from API names alone (URLDownloadToFile, CreateProcess, WS2_32, Ntdll, SeDebugPrivilege) when source and docs are absent - schema-from-metadata applied to executables.
- We meet anti-analysis countermeasures - anti-disassembly, anti-debug (IsDebuggerPresent/PEB), anti-VM (Red Pill/rdtsc), process injection - and need to recognize and defeat them rather than be misled by a deliberately deceptive sample.

## Principles

- The four-quadrant method is the analytical spine: static vs dynamic crossed with basic vs advanced, each quadrant revealing a slice; you escalate quadrants only as cheaper ones run out, never starting with the disassembler.
- The goal is indicators, not understanding-for-its-own-sake: host-based signatures (files, registry, mutexes) and network signatures are the deliverable, and the Danger-of-Overanalysis hierarchy (surface -> communication-method -> operational-replication -> full-code-coverage) tells you when to stop.
- Content-based indicators outlast address-based ones: IPs and domains are cheap for the attacker to rotate, so durable detection targets fundamental traffic characteristics, and you must isolate host-derived variable fields before they poison a signature.
- Verification by cross-sampling is load-bearing: run the malware on multiple hosts and multiple times to learn which bytes are random-seeded vs host-derived vs static, or you write a confident, reproducible, wrong rule from a sample size of one or two.
- Analysis is an arms race and OPSEC governs: malware actively detects sandboxes, debuggers, and VMs and deceives the disassembler, while your own investigative footprint (DNS resolutions, canary domains, search-crawler triggers) can reveal you to the operator.
