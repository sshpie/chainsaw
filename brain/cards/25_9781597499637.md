# 25. SQL Injection Attacks and Defense

**ISBN** 9781597499637  |  **Lobe** offensive

> The full-lifecycle SQLi field manual: per-platform discovery, blind and out-of-band extraction, OS pivot, defense-in-depth, and forensic confirmation of attempted-vs-successful. Reach for it as both the data-plane injection bible and the canonical analog for any data-into-control-plane confusion (prompt injection included).

## Reach for this when

- A web/API parameter touches a SQL backend and you need to confirm injectability, not just flag a candidate (inline-function test, ' AND 1=1-- vs ' AND 1=2--, error fingerprint).
- The app returns nothing and no errors: you need blind (binary-search / bit-by-bit) or out-of-band (DNS/HTTP/SMTP/ICMP) extraction to turn a one-bit oracle into full data.
- You have a confirmed injection and want to escalate: UNION/error extraction, schema enumeration, privilege escalation (OPENROWSET sa brute, sp_addsrvrolemember, Oracle cursor injection), then OS command exec (xp_cmdshell, MySQL UDF, PostgreSQL libc system(), Oracle EXTPROC/DBMS_SCHEDULER).
- You need to filter-evade: case variation, /**/ comments, URL/double-URL/Unicode encoding, CHAR()/CHR(), %00, keyword nesting (SELSELECTECT), buffer truncation, or second-order injection that defeats input-only filtering.
- Post-incident: you must prove whether an injection attempt actually executed and succeeded (web logs vs execution plans vs transaction logs) and classify the payload static-vs-dynamic to scope recovery.
- Designing a safe data/control interface (SQL, NoSQL $where, XPath, LDAP, or an LLM tool-call) and you want the canonical parameterize/whitelist/canonicalize/least-privilege taxonomy.

## Principles

- Root cause is one thing: untrusted data crosses from the data plane into the SQL control plane via string concatenation. Every real fix keeps that boundary intact; everything else is impact-limiting.
- Parameterized statements (bind variables, compiled before data supplied) are the primary code fix but CANNOT parameterize identifiers (table/column names, ORDER BY) -> those still need whitelist validation. Know the gap.
- Whitelist beats blacklist absolutely; blacklists are always incomplete and only valid as a supplement combined with output encoding. Canonicalize (NFKC) BEFORE validating, because a quote has many encodings (%27, %2527, %u0027, &#39;, %ca%b9).
- Absence of errors or returned data is NOT a defense: blind inference and out-of-band channels extract anyway. Egress controls on the DB server matter as much as ingress.
- Least-privilege DB logins and stored-procedure-only access shrink blast radius more than any clever filter; if the app login has only EXECUTE on procs, a working injection yields little.
- Verification is load-bearing: 'logged attempt' (web logs) is not 'successful exploit' (execution plans / transaction logs). The same candidate-vs-finding distinction the methodology runs on.

## Moves

- Confirm injectability without breaking the page: numeric param ID=51-ASCII(2) (equals 1), string split sho'+'es (MSSQL) / sho'||'es (Oracle,PG) / sho' 'es (MySQL); then ' AND 1=1-- vs ' AND 1=2-- and the ') paren-closing variant.
- Fingerprint the DB by error string (Microsoft OLE DB, ORA-, MySQL, PostgreSQL) or by time delay: WAITFOR DELAY '0:0:10' (MSSQL), SLEEP(10)/BENCHMARK (MySQL), pg_sleep(10) (PG), DBMS_LOCK.SLEEP/UTL_INADDR (Oracle).
- UNION extraction: ORDER BY n to count columns, NULLs/CAST to reconcile types, UNION ALL SELECT to defeat image-column DISTINCT errors. Error-based fallback: CONVERT(INT,@@VERSION), GROUP BY/HAVING enumeration, Oracle utl_inaddr.get_host_name / CTXSYS.DRITHSX.SN.
- Blind: binary-search on ASCII(SUBSTRING(...)) or bit-by-bit (FN_REPLINTTOBITSTRING / bitwise AND) -> a byte in 7-8 boolean questions (worked example: 'sql08' in 115 requests, byte 14 in 8 questions).
- Out-of-band exfil when the app is silent: xp_dirtree + FN_VARBINTOHEXSTR over DNS (labels max 63 chars, UNC paths max 128), UTL_HTTP.REQUEST / HTTPURITYPE.getclob() over arbitrary TCP, UTL_SMTP email channel.
- OS pivot: xp_cmdshell or sp_OACREATE 'wscript.shell' (MSSQL), INTO DUMPFILE + UDF (MySQL), CREATE FUNCTION importing libc system() (PG), EXTPROC/DBMS_SCHEDULER/RUNJAVA (Oracle); consolidate via Meterpreter.
- Defend in code: Domain Driven Security value object (constructor enforces Pattern ^[a-z]{4,20}$ so invalid data cannot exist as the type), parameterized statements per stack (JDBC PreparedStatement, mysqli bind_param, pg_query_params $1, PDO), dbms_assert for un-parameterizable identifiers, double-quote encoding to the DB.
- Confirm forensically: Microsoft Log Parser SQL over IIS/Apache logs (spear-search LIKE '%pangolin%', bandwidth/hit anomalies), execution plans (sys.dm_exec_query_stats / gv$sql), transaction logs (fn_dblog, V$LOGMNR_CONTENTS, mysqlbinlog), AFTER SERVERERROR trigger. Image first with dcfldd + SHA1, chain of custody, pull network cable not power.
- NEVER inject OR 1=1 into an UPDATE/DELETE during assessment (resets every row); back up before testing; remember OWASP ZAP and pangolin inject it too.

## Watch out

- Currency gap: written ~2012. Predates ORM-heavy stacks, modern WAF/ML detection, and current cloud-managed DBs. Treat platform-specific defaults (xp_cmdshell enabled, PUBLIC grants) as historical baselines, verify against current advisories before asserting.
- ORMs are NOT automatically safe: raw-query escape hatches, .raw()/createNativeQuery, and dynamic ORDER BY still concatenate. The book's parameterization gap (identifiers can't bind) is exactly where ORM users get burned.
- Tool footprints are loud: sqlmap can generate 1300+ execution plans just reading a banner ('sore thumb' in the plan cache); pangolin leaves pangolin_test_table and hex payloads. If quiet matters, hand-craft inference, do not fire the automated tool.
- WAF/filter-evasion lists age fast: the specific bypasses (SELSELECTECT nesting, %00, /**/) get patched into rules. Use them as a technique class to derive new variants, not a copy-paste list; 0 results means generate variants, not stop.
- Destructive primitives: OR 1=1 into UPDATE/DELETE, INTO DUMPFILE overwriting files, sp_addsrvrolemember granting persistent sysadmin. These cross from read-only assessment into modification; gate them behind explicit authorization and back up first. Restraint ethic: enumerate the surface, do not exfiltrate or mutate.
- The analog to prompt injection is structural, not literal: parameterization has no clean LLM equivalent (you cannot 'bind' natural language away from instructions), so do not over-promise that the SQLi defense taxonomy fully solves prompt injection. It frames the problem; it does not close it.
